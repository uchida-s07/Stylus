## 1. 要求（Why）

- 関連する要求: G-1, G-6, G-7, P-6, P-7, P-8, P-9, P-10, J-8, J-9, J-10
- 解決したい課題: お金は数か月に一度、各自が使用履歴を見返して書き出して精算している。そのため、書き出しが面倒で精算の回数が減り1回で大きな額が動く（P-6）、請求漏れが起きる（P-7）、普段いくらたまっているか分からない（P-8）、「払った」「もらっていない」の行き違いが起きる（P-9）、まとめて届いた請求が何の分でいくらか確かめにくい（P-10）
- 対象ユーザー: 家族4人。主に請求するのは息子2人、請求されるのは母・父（「家庭」宛ては父母のどちらかが対応する）。ただし全員が請求する側にも、される側にもなりうる
- 成功の判断基準:
  1. お金を使ったその場で、スマホから請求を残せる
  2. 精算のとき、アプリを見れば「誰に・何の分で・いくら請求していて、どれが未払いか」が分かり、使用履歴を見返さずに済む。何か月かに一度まとめて精算するやり方は残ってよい
  3. 払った側が「払った」、受け取った側が「受け取った」を残し、両方が同じ状態を見られる
  4. 数か月ぶりに開いた父が、人に聞かずに自分宛て・「家庭」宛ての請求を確かめ、「払った」を残せる
  5. 何か月かに一度の精算の場面で、2人の間のまだ片付いていない請求を両方向とも差し引きし、「どちらがどちらに合計何円渡すか」がアプリで分かる。払う側はその額を一括で「払った」にでき、受け取る側はそのまとまった送金を一括で「受け取った」にできる（例：せいご→母 3,000円、母→せいご 1,000円 なら「母がせいごに 2,000円」）

### 要件の変更後の姿

#### この領域で使うことば

- **当事者**：請求する側と請求先。家族の1人か、「家庭」。「家庭」は父母を1つにまとめた相手として扱う
- **関係者**：当事者が家族の1人ならその人、「家庭」なら父と母の2人
- **空白**：半角空白・タブ・改行と全角空白（U+3000）。家族の表示名（AUTH-F-001）と揃える
- **名義**：請求・精算を誰として行うか。「自分」か「家庭」。「家庭」の名義は親だけが使える（glossary の「立場」（親・料理担当）とは別のことば）
- **側**：請求する側・請求先側、精算の払う側・受け取る側。どの操作ができるかは側で決まる（下の2行）
- **請求の状態**：請求中 → 支払済 → 確認済。ほかに 差し戻し、取消。確認済と取消は終わりの状態で、そこからは変わらない
- **精算**：2人の当事者の間の請求中の請求を、両方向とも差し引いてまとめて払う・受け取ること
- **請求する側の操作**（直す・出し直す・取り消す・受け取った・受け取っていない）は請求する側の関係者が、**請求先側の操作**（払った・差し戻す・「払った」の取り消し）は請求先側の関係者が行う。「家庭」が当事者なら父母のどちらが行ってもよく、経過には実際に操作した家族を残す
- **精算の操作**（まとめて払った・まとめて受け取った・精算ごと戻す）は、含まれる各請求の向きではなく、精算の**払う側・受け取る側**で決まる。払う側の関係者は「まとめて払った」と、精算の「払ったを取り消す」を、受け取る側の関係者は「まとめて受け取った」と、精算の「受け取っていない」を行う

#### この領域で共通の振る舞い

- **行えない操作のボタンは出さない**：請求・精算の状態と、自分がどの側かに合わない操作のボタンは、画面に出さない。API でも受け付けない（側が違えば 403、状態が違えば 409）
- **開いた後に変わっていたとき**：画面を開いた後に状態が変わっていて操作が通らなかったときは「請求の状態が変わりました。もう一度開いてください。」と出し、最新の請求を出す。状態は同じで中身（金額など）が変わっていたときは「請求の中身が変わりました。もう一度確かめてください。」、精算に含まれる請求が変わっていたときは「精算の中身が変わりました。もう一度確かめてください。」と出す
- **書き込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度お試しください。」、保存に失敗したときは「保存できませんでした。時間をおいてもう一度お試しください。」と出す。入力した内容は残し、請求・精算は操作の前のまま
- **読み込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度開いてください。」、それ以外は「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と出す
- **知らせの確かめ方**：上の知らせの文言は、代表の受入基準（書き込みは MONEY-F-001/AC-13 と MONEY-F-011/AC-7、読み込みは MONEY-F-004/AC-7・AC-8）で確かめる。各要件の「処理に失敗」は、一部だけが変わらないなど、その要件に固有の結果があるものだけを受入基準にする

#### MONEY-F-001 請求を登録できる（新規）

- **概要**: 請求先・金額・カテゴリー・件名・メモ（任意）・発生日を入れて請求を登録する。請求する側は自分。親は「家庭」も選べる。登録した請求は請求中になり、関係者の一覧に出る
- **事前条件**: AUTH-F-002 でログイン済み。カテゴリーが1つ以上ある（MONEY-F-013）
- **正常フロー**: お金の画面で「請求する」を押す → 請求先・金額・カテゴリー・件名・発生日（既定は今日）・メモを入れる。親は請求する側を「自分」か「家庭」から選ぶ（既定は自分） → 「請求する」を押す → 請求中として保存され、一覧に出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 請求先・金額・カテゴリー・件名・発生日のどれかが空なら登録を止め、その項目に「入力してください」と出す。件名は空白だけも空とみなす。メモは空でよい。カテゴリーが1つも無いときは「先にカテゴリーを追加してください」と出し、カテゴリーの追加へ進めるようにする
  - 対象外・想定外: 次の場合は登録を止めて理由を出す。
    - 金額が1円以上9,999,999円以下の整数でない（0・マイナス・小数・範囲外）
    - 金額に全角の数字や数字でない文字が入っている（「半角の数字で入力してください」と出す。全角を半角に直して受け付けることはしない）
    - 件名が50文字を超える。メモが500文字を超える
    - 発生日が今日（日本時間）より後、または 2020-01-01 より前（打ち間違いを止めるため）
    - 自分を請求先にした。親が「家庭」宛てにした。「家庭」として請求するときに、請求先を父か母にした（「家庭」の請求先は息子だけ）
    - 選んだカテゴリーが、登録の直前に削除されていた（「カテゴリーが見つかりません。選び直してください」）

    親でない家族が「家庭」として請求しようとしたら、API が 403 を返す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。「請求する」を続けて2回押しても、登録されるのは1件だけ。通信できないと出た後に入力を直して押し直したとき、最初の登録がすでに保存されていたら、登録を止めて「この請求はすでに登録されています。一覧で確かめて、必要なら直してください。」と出す（API は 409）
- **受入基準**:
  - AC-1: Given せいごがログインしている / When 請求先「母」・金額 3,000・カテゴリー「医療費」・件名「歯医者」・発生日 2026-10-04 で請求する / Then 請求中の請求が1件でき、せいごと母の一覧に出て、父とくうごの一覧には出ない
  - AC-2: Given 母がログインしている / When 請求する側「家庭」・請求先「くうご」・金額 5,000・カテゴリー「日用品」・件名「スマホの修理代」で請求する / Then 請求する側が「家庭」の請求中の請求ができ、母・父・くうごの一覧に出る
  - AC-3: 〔例外：入力が空〕Given せいごが請求の入力をしている / When 件名を空白だけにして「請求する」を押す / Then 請求は作られず、件名に「入力してください」と出る
  - AC-4: 〔例外：対象外の入力〕Given せいごが請求の入力をしている / When 金額を 0、10,000,000、1.5、-100 のそれぞれにして請求する / Then どれも請求は作られない
  - AC-5: Given せいごが請求の入力をしている / When 金額を 1 と 9,999,999 のそれぞれにして請求する / Then どちらも請求中の請求ができる
  - AC-6: 〔例外：対象外の入力〕Given 日本時間で 2026-10-04 23:59 / When 発生日 2026-10-05 で請求する / Then 請求は作られない
  - AC-7: 〔例外：対象外の入力〕Given せいごがログインしている / When 請求先を自分（せいご）にして請求する / Then 請求は作られない
  - AC-8: 〔例外：対象外の入力〕Given 母がログインしている / When 請求先を「家庭」にして請求する / Then 請求は作られない
  - AC-9: 〔例外：対象外の入力〕Given 父がログインしている / When 請求する側「家庭」・請求先「母」で請求する / Then 請求は作られない
  - AC-10: 〔例外：対象外の入力〕Given 親でないせいごのトークン / When 請求する側を「家庭」にして登録の API を呼ぶ / Then 403 が返り、請求は作られない
  - AC-11: 〔例外：対象外の入力〕Given せいごがカテゴリー「食費」を選んで入力している間に、「食費」が削除された / When 「請求する」を押す / Then 請求は作られず、「カテゴリーが見つかりません。選び直してください」と出る
  - AC-12: 〔例外：入力が空〕Given カテゴリーが1つも無い / When 請求の入力を開く / Then 「先にカテゴリーを追加してください」と出て、カテゴリーの追加へ進める
  - AC-13: 〔例外：処理に失敗〕Given 通信できない / When AC-1 と同じ値（請求先「母」・金額 3,000・カテゴリー「医療費」・件名「歯医者」・発生日 2026-10-04）を入れて「請求する」を押す / Then 「通信できません。電波の良いところでもう一度お試しください。」と出て、入力した内容が残っている
  - AC-14: Given せいごが AC-1 と同じ値を入れた / When 「請求する」を続けて2回押す / Then 請求は1件だけできる
  - AC-15: 〔例外：対象外の入力〕Given せいごが請求の入力をしている / When 件名を51文字にして請求する、メモを501文字にして請求する / Then どちらも請求は作られない（件名50文字・メモ500文字なら作られる）
  - AC-16: 〔例外：処理に失敗〕Given せいごが金額 3,000 で「請求する」を押し、請求は保存されたが応答が届かず「通信できません。電波の良いところでもう一度お試しください。」と出た / When 金額を 3,500 に直して「請求する」を押す / Then 新しい請求は作られず、「この請求はすでに登録されています。一覧で確かめて、必要なら直してください。」と出て、一覧には 3,000円 の請求が1件だけある
  - AC-17: Given 日本時間で 2026-10-05 00:30（UTC では 2026-10-04 15:30） / When 発生日 2026-10-05 で請求する / Then 請求中の請求ができる
  - AC-18: 〔例外：対象外の入力〕Given せいごが請求の入力をしている / When 発生日を 2019-12-31 にして請求する / Then 請求は作られない（発生日 2020-01-01 なら作られる）
  - AC-19: 〔例外：対象外の入力〕Given せいごが請求の入力をしている / When 金額に全角で「３０００」と入れて「請求する」を押す / Then 請求は作られず、金額に「半角の数字で入力してください」と出る

#### MONEY-F-002 請求中・差し戻された請求を直して出し直せる（新規）

- **概要**: 請求する側の関係者が、請求中か差し戻しの請求の金額・カテゴリー・件名・メモ・発生日を直す。差し戻しの請求は、直して（直さなくても）出し直すと請求中に戻る。請求する側と請求先は直せない（取り消して登録し直す）
- **事前条件**: MONEY-F-001 で登録した請求が請求中か差し戻し。操作する人が請求する側の関係者
- **正常フロー**: 請求の中身の画面で「直す」を押す → 項目を直す → 「保存する」（差し戻しのときは「出し直す」）を押す → 保存され、経過に「直した」（差し戻しからは「出し直した」）が日時と操作した家族とともに残る。差し戻しは請求中に戻る
- **例外・バリデーション**:
  - 入力が空・欠けている: MONEY-F-001 と同じ（空の項目があれば止める）
  - 対象外・想定外: 値の範囲は MONEY-F-001 と同じ。支払済・確認済・取消の請求は直せない（「直す」を出さない）。請求先側の関係者は直せない（API は 403）。直す画面を開いている間に相手が払った・差し戻したなどで状態が変わっていたら、保存を止めて「請求の状態が変わりました。もう一度開いてください。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。請求は直す前のまま
- **受入基準**:
  - AC-1: Given せいご→母 の請求中の請求（3,000円） / When せいごが金額を 2,500 に直して保存する / Then 金額は 2,500円、状態は請求中のままで、経過に「直した」とせいごの表示名が残る
  - AC-2: Given 母が差し戻した せいご→母 の請求 / When せいごが件名を直して「出し直す」を押す / Then 状態が請求中に戻り、経過に「出し直した」が残り、母の一覧で請求中として出る
  - AC-3: 〔例外：対象外の入力〕Given せいご→母 の支払済の請求 / When せいごが直す / Then 直せず、請求は変わらない
  - AC-4: 〔例外：対象外の入力〕Given せいご→母 の請求中の請求 / When 母（請求先）が直す API を呼ぶ / Then 403 が返り、請求は変わらない
  - AC-5: 〔例外：対象外の入力〕Given せいごが せいご→母 の請求を直す画面を開いている間に、母が「払った」にした / When せいごが保存する / Then 「請求の状態が変わりました。もう一度開いてください。」と出て、金額などは変わらない
  - AC-6: Given 母が登録した 家庭→くうご の請求中の請求 / When 父が金額を直して保存する / Then 保存され、経過に「直した」と父の表示名が残る
  - AC-7: 〔例外：入力が空〕Given せいご→母 の請求中の請求（件名「歯医者」） / When せいごが件名を空白だけにして保存する / Then 保存されず、件名は「歯医者」のまま
  - AC-8: 〔例外：対象外の入力〕Given せいご→母 の請求中の請求（3,000円） / When せいごが金額を 0 に直して保存する / Then 保存されず、金額は 3,000円のまま
- **対応する要求**: G-6, G-7, P-9, J-8

#### MONEY-F-003 請求を取り消せる（新規）

- **概要**: 請求する側の関係者が、請求中か差し戻しの請求を取り消す。取り消した請求は取消になり、消えずに履歴（片付いた請求）に残る。合計・精算には入らない
- **事前条件**: 請求が請求中か差し戻し。操作する人が請求する側の関係者
- **正常フロー**: 請求の中身の画面で「取り消す」を押す → 「この請求を取り消しますか？」で「取り消す」を選ぶ → 取消になり、経過に「取り消した」が残る

| 項目 | 区分 | 理由 |
|------|-----|------|
| 割り勘（1件の請求を複数人に分ける） | 後回し | 一旦なくす。入れる場合は請求の中に「払う人ごとの行」ができる（handoff 3.1） |
| 請求の集計（年別・カテゴリー別。医療費控除など） | 後回し | 今回の困りごと（書き出し・漏れ・行き違い）は記録と精算で足りる（handoff 3.1） |
| 請求・支払いの通知 | 後回し | 通知は「作れない日」の spec で Web プッシュの仕組みを入れてから足す（handoff 3.1） |
| 決済（お金の実際のやり取り） | やらない | vision の非目標。アプリは記録だけを扱う |
| レシート・領収書の画像 | やらない | vision の非目標 |
| 「かかった額」と「請求額」の区別 | やらない | vision の非目標。補助の範囲は請求する側が考えて金額を決める |
| カテゴリーの名前の変更 | やらない | 新しく追加して古いほうを削除すれば足りる（handoff 2.4） |

## 3. 変更差分

詳しい持ち方と理由は design.md。

### DB

- 表を4つ足す。どれも RLS を有効にし、ポリシーは作らない（COMMON-N-003）
  - `bill_categories`（カテゴリー）：名前（前後の空白を除いて一意）。マイグレーションで 医療費・食費・交通費・日用品・その他 を入れる
  - `bills`（請求）：請求する側・請求先（家族の ID。「家庭」は NULL）、金額、カテゴリー（削除は RESTRICT）、件名、メモ、発生日、状態、版（同時更新の検出用）、含まれる精算、登録した家族、二重登録を防ぐための ID（`request_id`）、日時
  - `bill_events`（経過）：請求、種類、操作した家族、理由、精算、日時、足した順（同じ日時の経過の並び順のため）
  - `settlements`（精算）：払う側・受け取る側（家族の ID。「家庭」は NULL）、精算額、状態（支払済・確認済・戻した）、払った家族と日時、受け取った家族と日時、戻した家族と日時
- `members` は変えない。ただし、新しい表から `members` への外部キーを `ON DELETE RESTRICT` にするので、お金の記録がある家族の行は消せなくなる（design.md「当事者（『家庭』）の表し方」）。/spec-close で architecture.md の家族の登録の仕方にも注記する
