## 1. 要求（Why）

- 関連する要求: P-4, P-5, G-5, J-6, J-7
- 解決したい課題: 車1台を母と息子2人で共有しているが、いつ・誰が・何時まで使うかが分からず、使おうとしたら先に乗っていかれていることがある（P-4）。少し先の日に使いたくても、前もって家族に伝える手段が無い（P-5）
- 対象ユーザー: 車を使う人（母・息子2人）。父は単身赴任中は車を使わないが、一時帰国中はほかの家族と同じように予約を入れる（特別な扱いはしない）
- 成功の判断基準: vision の成功指標のとおり、使おうとしたら先に乗っていかれていた、が無くなる（運用で目視）。家族は乗る前にアプリに予約を入れる（予約を入れずに乗る使い方は、直前に予約を入れてもらう運用で足り、機能は作らない。handoff 2.2）。予定の調整（取り合いの解決）は家族が話し合って行い、アプリは先に入れた予約を記録するだけ（vision の非目標）

#### この領域で使うことば

- **予約**：1台の車を、開始日時から終了日時まで使う予定。予約した家族・行き先（任意）・メモ（任意）を持つ
- **日時**：日本時間で、分まで扱う（秒は持たない）。曜日は日本時間の日付で決める
- **時間が重なる**：同じ車の2つの予約で、一方の開始日時が他方の終了日時より前で、かつ他方の開始日時が一方の終了日時より前のとき。終了日時と次の開始日時が同じ（12:00 に終わり、12:00 に始まる）なら重ならない
- **これからの予約**：終了日時が今より後の予約。そのうち、開始日時が今以前のものを**使用中**と呼ぶ
- **終わった予約**：終了日時が今以前の予約。履歴に出る
- **車の状態**：「使う」か「使わない」。「使わない」の車は、新しい予約の選択肢に出ない
- **予約した本人**：予約を入れた家族。予約を直す・取り消すのは本人だけ（管理者・親も例外なし）
- **空白**：半角空白・タブ・改行と全角空白（U+3000）。お金（MONEY）と揃える

#### この領域で共通の振る舞い

- **誰でも見られ、誰でも使える**：車と予約は家族全員が見られる。車の登録・予約は、父を含め家族の誰でもできる（ロール・立場は問わない）
- **行えない操作のボタンは出さない**：本人でない予約、使用中・終わった予約に合わない操作のボタンは、画面に出さない。API でも受け付けない（本人でなければ 403、予約の状態（これから・使用中・終わった）に合わなければ 409）
- **開いた後に変わっていたとき**：画面を開いた後に予約の中身が変わっていて操作が通らなかったときは「予約の中身が変わりました。もう一度確かめてください。」と出し、最新の予約を出す。予約が取り消されていたときは「この予約は見つかりません。」、車が削除されていたときは「この車は見つかりません。」と出す
- **書き込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度お試しください。」、保存に失敗したときは「保存できませんでした。時間をおいてもう一度お試しください。」と出す。入力した内容は残し、車・予約は操作の前のまま
- **読み込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度開いてください。」、それ以外は「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と出す
- **知らせの確かめ方**：上の知らせの文言は、代表の受入基準（書き込みは CAR-F-004/AC-14・AC-15、読み込みは CAR-F-005/AC-6・AC-7）で確かめる。各要件の「処理に失敗」は、その要件に固有の結果があるものだけを受入基準にする

#### CAR-F-001 車を登録できる（新規）

- **概要**: 家族の誰でも、名前を付けて車を登録できる。登録した車は「使う」の状態になり、家族全員の予約の選択肢に出る。最初から車「BMW」が1台（「使う」）登録されている
- **事前条件**: AUTH-F-002 でログイン済み
- **正常フロー**: 車の管理の画面で名前を入れる → 「登録する」を押す → 車の一覧と、予約の入力の車の選択肢に出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 名前が空（空白だけを含む）なら止めて「入力してください」と出す
  - 対象外・想定外: 名前（前後の空白を除いたもの）が20文字を超えたら止める。前後の空白を除いて同じ名前の車（「使わない」の車を含む）があるときは、止めて「同じ名前の車があります」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す
- **受入基準**:
  - AC-1: Given せいごがログインしている / When 車「ノア」を登録する / Then 母が予約の入力を開くと、車の選択肢に「ノア」が出る
  - AC-2: 〔例外：入力が空〕Given 車の管理の画面 / When 名前を空白だけ（"　"）にして登録する / Then 登録されず「入力してください」と出る
  - AC-3: 〔例外：対象外の入力〕Given 車「ノア」がある / When 「　ノア　」（前後が全角空白）を登録する / Then 登録されず「同じ名前の車があります」と出る
  - AC-4: 〔例外：対象外の入力〕Given 「使わない」の車「ノア」がある / When 「ノア」を登録する / Then 登録されず「同じ名前の車があります」と出る
  - AC-5: 〔例外：対象外の入力〕Given 車の管理の画面 / When 21文字の名前と20文字の名前をそれぞれ登録する / Then 21文字は登録されず、20文字は登録される
  - AC-6: Given アプリを使い始めたばかり（車を誰も登録・変更・削除していない） / When 予約の入力を開く / Then 車の選択肢に「BMW」だけが出て、最初から選ばれている
- **対応する要求**: G-5, J-6

#### CAR-F-002 車を「使わない」にできる（「使う」に戻せる）（新規）

- **概要**: 家族の誰でも、車を「使わない」にできる。「使わない」の車は新しい予約の選択肢から外れるが、車の一覧と、その車の予約（これから・履歴）は残る。「使う」に戻すと、また選択肢に出る
- **事前条件**: CAR-F-001 で車が登録されている
- **正常フロー**: 車の管理の画面で「使わないにする」を押す → 「『ノア』を使わないにしますか？」の確認（その車にこれからの予約があれば「この車にはこれからの予約が N 件あります。予約はそのまま残ります。」を添える）で「使わないにする」を選ぶ → 予約の選択肢から外れ、車の一覧では「使わない」と出る。「使う」に戻すときは「使うに戻す」を押す（確認は出さない）
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら何もしない
  - 対象外・想定外: これからの予約がある車も「使わない」にできる（予約は消さず、本人がそのまま直す・取り消すことができる）。開いた後にほかの家族が同じ操作を済ませていたときは、そのまま成功とする（同じ状態になるだけ）。車が削除されていたときは「この車は見つかりません。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出す。車の状態は変わらない
- **受入基準**:
  - AC-1: Given 「使う」の車「ノア」 / When 母が「使わないにする」を押し、確認で「使わないにする」を選ぶ / Then 予約の入力の車の選択肢に「ノア」が出ず、車の管理の画面では「ノア」に「使わない」と出る
  - AC-2: Given 「使わない」の車「ノア」 / When 「使うに戻す」を押す / Then 予約の入力の車の選択肢に「ノア」が出る
  - AC-3: 〔例外：対象外の入力〕Given 「ノア」にくうごのこれからの予約（10月10日 9:00〜12:00）が1件ある / When 「使わないにする」を押す / Then 確認に「この車にはこれからの予約が1件あります。予約はそのまま残ります。」と出て、「使わないにする」を選んだ後も、その予約は予定に残る
  - AC-4: 〔例外：入力が空〕Given 「使う」の車「ノア」 / When 「使わないにする」を押し、確認で「キャンセル」を選ぶ / Then 「ノア」は「使う」のまま
  - AC-5: 〔例外：対象外の入力〕Given 母が「ノア」の「使わないにする」の確認を開いている間に、せいごが「ノア」を削除した / When 母が「使わないにする」を選ぶ / Then 「この車は見つかりません。」と出る
  - AC-6: Given 母が「ノア」の「使わないにする」の確認を開いている間に、せいごが「ノア」を「使わない」にした / When 母が「使わないにする」を選ぶ / Then 知らせは出ず、「ノア」は「使わない」になっている
- **対応する要求**: G-5

#### CAR-F-003 予約の無い車を削除できる（新規）

- **概要**: 家族の誰でも、予約が1件も無い車（取り消した予約は数えない。CAR-F-007）を削除できる。予約が1件でもある車（これから・使用中・終わったのどれでも）は削除できず、代わりに「使わない」にする（CAR-F-002）
- **事前条件**: CAR-F-001 で車が登録されている
- **正常フロー**: 車の管理の画面で「削除」を押す → 「『ノア』を削除しますか？」の確認で「削除する」を選ぶ → 車の一覧と予約の選択肢から消える
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら何もしない
  - 対象外・想定外: 予約がある車には「削除」を出さない。API で削除しようとしたら止める。画面を開いた後にその車に予約が入ったときは、止めて「この車には予約があるため削除できません。使わないにしてください。」と出す。すでに削除されていたら「この車は見つかりません。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出す。車は残る
- **受入基準**:
  - AC-1: Given 予約が1件も入ったことのない車「ノア」 / When せいごが「削除」を押し、確認で「削除する」を選ぶ / Then 「ノア」が車の一覧と予約の選択肢から消える
  - AC-2: 〔例外：対象外の入力〕Given 終わった予約が1件だけある車「ノア」 / When 車の管理の画面を開く / Then 「ノア」に「削除」は出ず、「使わないにする」が出る
  - AC-3: 〔例外：対象外の入力〕Given 終わった予約が1件だけある車「ノア」 / When 削除の API を呼ぶ / Then 409 が返り、「ノア」は残る
  - AC-4: Given 取り消した予約しか無い車「ノア」 / When 削除する / Then 削除される
  - AC-5: 〔例外：対象外の入力〕Given せいごが「ノア」の削除の確認を開いている間に、くうごが「ノア」を予約した / When せいごが「削除する」を選ぶ / Then 削除されず「この車には予約があるため削除できません。使わないにしてください。」と出る
  - AC-6: 〔例外：入力が空〕Given 予約の無い車「ノア」 / When 「削除」を押し、確認で「キャンセル」を選ぶ / Then 「ノア」は残る
  - AC-7: 〔例外：対象外の入力〕Given せいごが「ノア」の削除の確認を開いている間に、母が「ノア」を削除した / When せいごが「削除する」を選ぶ / Then 「この車は見つかりません。」と出る
- **対応する要求**: G-5

#### CAR-F-004 車の予約を入れられる（新規）

- **概要**: 家族の誰でも、車・開始日時・終了日時・行き先（任意）・メモ（任意）を入れて予約する。同じ車で時間が重なる予約がすでにあれば、後から入れようとした予約は止める（先に入れた予約が優先）。入れた予約は家族全員の予定に出る
- **事前条件**: AUTH-F-002 でログイン済み。「使う」の車が1台以上ある（CAR-F-001）
- **正常フロー**: 車の画面で「予約する」を押す → 車（「使う」の車が1台だけなら最初から選ばれている）・開始日時・終了日時・行き先・メモを入れる → 「予約する」を押す → 予約が保存され、予定に出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかが空なら止め、その項目に「入力してください」と出す。行き先・メモは空でよい（空白だけなら空とみなす）。「使う」の車が1台も無いときは「先に車を登録してください」と出し、車の管理の画面へ進めるようにする
  - 対象外・想定外: 次の場合は止めて理由を出す。
    - 終了日時が開始日時と同じか前（「終了は開始より後にしてください」）
    - 終了日時が今以前（「終了の日時が過ぎています」）。開始日時は今より前でもよい（乗ってから入れたとき）
    - 行き先（前後の空白を除いたもの）が50文字を超える。メモが500文字を超える
    - 同じ車で時間が重なる予約がある（「その時間は〈表示名〉の予約（〈開始〉〜〈終了〉）と重なっています」。自分の予約と重なるときも同じ）。同時に送られた2つの予約が重なるときは、先に保存された方だけが残る
    - 選んだ車が、入力している間に「使わない」になっていた（「この車は今は予約できません。選び直してください」）、または削除されていた（「この車は見つかりません。」）
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。「予約する」を続けて2回押しても、予約されるのは1件だけ。通信できないと出た後に入力を直して押し直したとき、最初の予約がすでに保存されていたら、止めて「この予約はすでに登録されています。予定で確かめて、必要なら直してください。」と出す
- **受入基準**:
  - AC-1: Given 日本時間 2026-10-07 20:00、車「ノア」があり、くうごがログインしている / When 車「ノア」・開始 2026-10-10 9:00・終了 2026-10-10 12:00・行き先「大学」で予約する / Then 予約が1件でき、母が車の画面を開くと「10月10日(土)」の下に「ノア くうご 9:00〜12:00 大学」が出る
  - AC-2: 〔例外：対象外の入力〕Given 母の「ノア」の予約（10月10日 10:00〜11:00） / When くうごが「ノア」を 10月10日 9:00〜12:00 で予約する / Then 予約は作られず「その時間は母の予約（10月10日(土) 10:00〜11:00）と重なっています」と出る
  - AC-3: Given くうごの「ノア」の予約（10月10日 9:00〜12:00） / When 母が「ノア」を 10月10日 12:00〜15:00 で、せいごが 10月10日 8:00〜9:00 で予約する / Then どちらも予約できる
  - AC-4: 〔例外：対象外の入力〕Given くうごの「ノア」の予約（10月10日 9:00〜12:00） / When 母が「ノア」を 10月10日 11:59〜15:00 で予約する / Then 予約は作られない
  - AC-5: Given 車「ノア」と「フィット」があり、くうごの「ノア」の予約（10月10日 9:00〜12:00） / When 母が「フィット」を 10月10日 9:00〜12:00 で予約する / Then 予約できる
  - AC-6: 〔例外：対象外の入力〕Given 「ノア」に予約が無い / When くうごの 10月10日 9:00〜12:00 と、せいごの 10月10日 10:00〜13:00 の予約の API が同時に呼ばれる / Then 予約は1件だけでき、もう一方には 409 が返る
  - AC-7: 〔例外：入力が空〕Given くうごが予約の入力をしている / When 終了日時を空にして「予約する」を押す / Then 予約は作られず、終了日時に「入力してください」と出る
  - AC-8: 〔例外：対象外の入力〕Given くうごが予約の入力をしている / When 10月10日 12:00〜12:00 と、10月10日 12:00〜11:00 のそれぞれで予約する / Then どちらも作られず「終了は開始より後にしてください」と出る
  - AC-9: Given 日本時間 2026-10-07 20:00 / When 10月7日 19:00〜22:00 で予約する / Then 予約ができ、予定に「使用中」と出る
  - AC-10: 〔例外：対象外の入力〕Given 日本時間 2026-10-07 20:00 / When 10月7日 18:00〜20:00 で予約する / Then 予約は作られず「終了の日時が過ぎています」と出る
  - AC-11: Given 日本時間 2026-10-07 20:00 / When 2026-10-10 9:00〜2026-10-31 9:00（21日間）と、開始 2027-12-01 9:00・終了 2027-12-01 12:00（1年以上先）のそれぞれで予約する / Then どちらも予約できる（長さと、何日先までかに上限は無い）
  - AC-12: 〔例外：対象外の入力〕Given くうごが「ノア」を選んで入力している間に、「ノア」が「使わない」になった / When 「予約する」を押す / Then 予約は作られず「この車は今は予約できません。選び直してください」と出る
  - AC-13: 〔例外：入力が空〕Given 「使う」の車が1台も無い / When 車の画面で「予約する」を押す / Then 「先に車を登録してください」と出て、車の管理の画面へ進める

#### CAR-F-006 自分の予約を直せる（新規）

- **概要**: 予約した本人が、まだ始まっていない予約の車・開始日時・終了日時・行き先・メモを直せる。使用中の予約は、終了日時・行き先・メモだけを直せる（延ばすとき、早く返したとき）。終わった予約は直せない
- **事前条件**: CAR-F-004 で本人が入れた、これからの予約がある
- **正常フロー**: 予約を開く → 「直す」を押す → 中身を直す → 「保存する」を押す → 予定に直した中身が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかを空にしたら止め、その項目に「入力してください」と出す
  - 対象外・想定外: 入力の条件は CAR-F-004 と同じ（終了は開始より後、文字数、時間の重なり。長さと何日先までかに上限は無い）。ただし次が違う。
    - 直す前の自分の予約とは、重なりを数えない
    - まだ始まっていない予約は、終了日時が今以前になる直し方はできない（「終了の日時が過ぎています」）
    - 使用中の予約は、車と開始日時を変えられない（入力欄を出さず、送らない。API に車・開始日時を両方含めて送ったら、値が同じでも 409。片方だけを送る要求は形が違うので 400）。終了日時は開始日時より後なら今より前にしてもよい（早く返した時刻を残す）。そうした予約は終わった予約になり、履歴へ移る
    - 「使わない」の車へは移せない（「この車は今は予約できません。選び直してください」）。予約している車が「使わない」になっていても、車を変えずに直すことはできる。移す先の車が、直している間に削除されていたら止めて「この車は見つかりません。」と出す
    - 本人でない予約には「直す」を出さない。API で直そうとしたら 403
    - 終わった予約には「直す」を出さない。API で直そうとしたら 409。直している間に予約が終わったときは「この予約はもう終わっているため直せません。」と出す
    - まだ始まっていない予約を直している間に、その予約が始まったときは、何を変えたかにかかわらず止めて「この予約はもう始まっています。もう一度開いてください。」と出し、最新の予約を出す
    - 開いた後に、本人がほかの端末で直していた、または取り消していたときは、「開いた後に変わっていたとき」の知らせを出す

  - 対象外・想定外: CAR-F-001 と同じ条件（20文字まで、前後の空白を除いてほかの車と同じ名前は「同じ名前の車があります」）。自分と同じ名前のまま保存したときは、何も変えずに成功とする。開いた後に車が削除されていたら「この車は見つかりません。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。名前は変わらない
- **受入基準**:
  - AC-1: Given 車「ノア」に、終わった予約とこれからの予約が1件ずつある / When 名前を「ヴォクシー」に変える / Then 車の画面の予定と履歴の両方で、その予約の車の名前が「ヴォクシー」と出る
  - AC-2: 〔例外：入力が空〕Given 車「ノア」 / When 名前を空白だけにして保存する / Then 名前は「ノア」のままで「入力してください」と出る
  - AC-3: 〔例外：対象外の入力〕Given 車「ノア」と「フィット」 / When 「フィット」の名前を「ノア」に変える / Then 名前は「フィット」のままで「同じ名前の車があります」と出る
  - AC-4: 〔例外：対象外の入力〕Given 車「ノア」 / When 名前を21文字にして保存する / Then 名前は「ノア」のまま
  - AC-5: 〔例外：対象外の入力〕Given 母が「ノア」の名前を変えている間に、せいごが「ノア」を削除した / When 母が「保存する」を押す / Then 「この車は見つかりません。」と出る
- **対応する要求**: G-5

## 3. 変更差分

<!-- コードが正。現在のスキーマと API を読んだうえで差分だけ書く。 -->

詳しい持ち方と理由は design.md。

### DB

- 拡張 `btree_gist` を有効にする（Supabase の `extensions` スキーマ。時間の重なりを排他制約で防ぐため）
- 表を2つ足す。どちらも RLS を有効にし、ポリシーは作らない（COMMON-N-003）
  - `cars`（車）：名前（前後の空白を除いて1〜20文字、一意）、使うかどうか（既定は使う）、日時。マイグレーションで「BMW」（使う）を1台入れる
  - `car_reservations`（予約）：車（削除は RESTRICT）、予約した家族（削除は RESTRICT）、開始日時・終了日時（`timestamptz`、分まで。終了は開始より後）、行き先（任意、1〜50文字）、メモ（任意、1〜500文字）、版（同時更新の検出用。ADR-0008）、二重登録を防ぐための ID（`request_id`。予約した家族と組で一意）、日時。同じ車で `[開始, 終了)` が重なる行を排他制約で拒む
- 取り消した予約は行を消す（残さない）。そのため、車の削除を止める外部キー（RESTRICT）は、取り消していない予約だけで効く
- `members` は変えない。`car_reservations` から `members` への外部キーも RESTRICT なので、予約の記録がある家族の行は消せない（既存の「家族の登録を外す」の手順のとおり、行は消さず `auth_user_id` を NULL にする）

### API

すべて既存の共通処理（CORS → トークンの検証 → DB → 家族の照合）の後ろに足す。エラーの形は既存の `{ error: { code, message } }`。

| メソッドとパス | 中身 | 要件 |
|---|---|---|
| `GET /cars` | 車の一覧（ID・名前・使うかどうか・予約があるか・これからの予約の件数） | CAR-F-001〜006, CAR-F-009 |
| `POST /cars` | 車を登録する | CAR-F-001 |
| `PATCH /cars/:id` | 名前を変える、使う／使わないを切り替える | CAR-F-002, CAR-F-009 |
| `DELETE /cars/:id` | 予約の無い車を削除する | CAR-F-003 |
| `GET /car-reservations?view=upcoming` | これからの予約（使用中を含む）。開始の早い順 | CAR-F-005 |
| `GET /car-reservations?view=past&before=<カーソル>` | 終わった予約。終了の遅い順に30件と、続きのカーソル | CAR-F-008 |
| `POST /car-reservations` | 予約を入れる（`request_id` を付けて送る） | CAR-F-004 |
| `GET /car-reservations/:id` | 予約の中身 | CAR-F-005〜008 |
| `PATCH /car-reservations/:id` | 予約を直す（版を付けて送る。車・開始日時を両方含む要求は「まだ始まっていない予約の直し方」、両方含まない要求は「使用中の予約の直し方」として扱う。片方だけなら 400 `invalid_input`） | CAR-F-006 |
| `DELETE /car-reservations/:id` | 予約を取り消す（版は送らない。開いた後に本人が直していても取り消す） | CAR-F-007 |

- エラーの code を2つ足す：`overlap`（409。同じ車で時間が重なる予約がある）、`car_unavailable`（409。予約を入れるときに選んだ車、または直すときに移す先の車（今の車から変えるとき）が「使わない」。画面は「この車は今は予約できません。選び直してください」と出す）。`overlap` のときだけ、エラーの本文に重なった予約 `conflict: { displayName, startsAt, endsAt }` を付ける（400 の `fields` と同じく、code ごとに付く項目。`packages/shared` のエラーのスキーマに任意の項目として足す）。画面はこれを日本時間で表示して知らせの文言を作る
- 既存の code の使う場面を広げる：`duplicate_name`（同じ名前の車）、`in_use`（予約のある車の削除）、`state_changed`（予約の中身が開いた後に変わった、使用中・終わった予約に合わない操作。車の「使わない」には使わない）、`already_registered`（二重登録を防ぐ ID が同じで中身が違う予約の登録）、`not_found`（取り消された予約、削除された車への車の操作）、`invalid_input`（予約を入れる・直すときに選んだ車が削除されていた。`fields.carId` に「この車は見つかりません。」。お金の削除されたカテゴリーと同じ形）
- 「今」は API の時計（`AppConfig.now`）で決める。使用中・終わったの判定と「終了の日時が過ぎています」の判定は API が行う
- `packages/shared` に足す：車・予約の Zod スキーマ、予約の状態（これから・使用中・終わった）の求め方、日本時間の日時の表示用の部品（`10月10日(土) 9:00` の形）
