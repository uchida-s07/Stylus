## 1. 要求（Why）

- 関連する要求: G-5, P-4, P-5, J-6, J-7
- 解決したい課題: 今の車の画面は、これからの予約を開始の日付ごとに並べた一覧なので、ある日のどの時間帯が埋まっていて、どこからどこまで使われているかを、行の時刻を読んで頭の中で組み立てなければならない。予約を入れるときも、日付と時刻を欄に打ち込む形で、空きを見ながら入れられない。オーナー（せいご）が spec 003 の開発環境での確認（T-30）で画面を触り、改善したほうがよいと判断した（2026-10-10 の依頼「車の予約について calendar のような表示でどこからどこまで使われているかをすぐに分かるようにして。また予約の登録操作もカレンダーのようにして」）。2026-10-11 に承認した形（1つの画面に月のカレンダーと時間割を並べ、長押しで範囲を選ぶ）を開発環境で確かめたところ（2026-10-16、tasks.md の T-13）、Google カレンダーのように月のカレンダーから日をタップして時間割へ移る形と、タップで出た枠を動かして時間を選ぶ形に直すことになった（決めたことは「4. 未決事項」の F-1〜F-5）
- 対象ユーザー: 車を使う人（母・息子2人。一時帰国中の父も）
- 成功の判断基準:
  - 車の画面を開いて、ある日のどの時間帯が埋まっているかを、時刻の文字を読まずに帯の位置で分かる
  - 予約を、時間割の上で枠を動かして時間を選ぶ操作から入れられる（日付と時刻を一から打たなくてよい）

#### CAR-F-004 車の予約を入れられる（変更）

- **変更前との差**: 日の時間割の空いた所をタップすると出る枠を動かして時間を選び、枠から出る入力からも予約を入れられるようにする。「予約する」ボタンからの入力の画面は残す。予定の見え方がカレンダーになるのに合わせて AC-1・AC-9 の確かめ方と、二重登録の知らせ（AC-17）の「予定で確かめて」を「車の画面で確かめて」に変え、AC-21〜AC-39 を足す（入力の出し方（ポップアップ・シート）と枠の動かし方は「3. 変更差分」の画面に書く）
- **概要（変更）**: 家族の誰でも、車・開始日時・終了日時・行き先（任意）・メモ（任意）を入れて予約する。日の時間割の空いた所をタップすると1時間の枠が出て、枠を動かして使いたい時間を選び、枠をタップすると、枠の開始と終了が入った入力が出る。「予約する」ボタンから入力の画面を開いて入れることもでき、保存の後はその予約の開始の日の時間割の画面に戻る。同じ車で時間が重なる予約がすでにあれば、後から入れようとした予約は止める（先に入れた予約が優先）。入れた予約は家族全員のカレンダーに出る
- **事前条件**: AUTH-F-002 でログイン済み。「使う」の車が1台以上ある（CAR-F-001）
- **正常フロー（変更）**: 車の画面の月のカレンダーで日をタップする → その日の時間割の、使いたい時間の空いた所をタップする → タップした所から1時間の枠が出る → 枠の端を引いて伸び縮みさせる・枠を引いて動かす（15分刻み） → 枠をタップする → 開始日時と終了日時が入った入力が出る（車は「使う」の車が1台だけなら最初から選ばれている） → 車・日時を直し、行き先・メモを入れる → 「予約する」を押す → 予約が保存されて入力が閉じ、時間割に帯が出る
- **例外・バリデーション（変更）**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかが空なら止め、その項目に「入力してください」と出す。行き先・メモは空でよい（空白だけなら空とみなす）。「使う」の車が1台も無いときは、「予約する」を押したときも時間割の空いた所をタップしたときも「先に車を登録してください」と出し（枠は出さない）、車の管理の画面へ進めるようにする。枠から出た入力は、何も保存せずに閉じられ、そのときは時間割の枠も消す。枠が出ているときに、枠の外の空いた所をタップすると枠が消える。入力の外側を押しても閉じない（入れた内容が不意に消えないように）。端末の「戻る」操作は、入力を閉じるだけで車の画面に残る
  - 対象外・想定外: 次の場合は止めて理由を出す。
    - 終了日時が開始日時と同じか前（「終了は開始より後にしてください」）
    - 終了日時が今以前（「終了の日時が過ぎています」）。開始日時は今より前でもよい（乗ってから入れたとき）
    - 行き先（前後の空白を除いたもの）が50文字を超える。メモが500文字を超える
    - 同じ車で時間が重なる予約がある（「その時間は〈表示名〉の予約（〈開始〉〜〈終了〉）と重なっています」。自分の予約と重なるときも同じ）。同時に送られた2つの予約が重なるときは、先に保存された方だけが残る
    - 選んだ車が、入力している間に「使わない」になっていた（「この車は今は予約できません。選び直してください」）、または削除されていた（「この車は見つかりません。」）
    - 枠は、ほかの予約の帯と重なる所へ動かしても、過ぎた時間でも置ける（別の車なら予約できるため。止めるかどうかは「予約する」を押したときに上の条件で決める）。帯をタップすると帯を押したことになるので、帯のある時間は帯の脇の空いた所をタップして枠を出す（出した後に枠を帯の上へ動かせる）。枠はその日の 0:00〜24:00 の中で動き、長さは15分より短くならない（23:00 より後をタップしたときは、枠を 24:00 で止めるので1時間より短くなる）。日を移ると（前の日・次の日・月へ戻る）枠は消える。日をまたぐ予約は、入力で終了の日付を直して入れる
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す（枠から出た入力は閉じない）。「予約する」を続けて2回押しても、予約されるのは1件だけ。通信できないと出た後に入力を直して押し直したとき、最初の予約がすでに保存されていたら、止めて「この予約はすでに登録されています。車の画面で確かめて、必要なら直してください。」と出す

#### CAR-F-006 自分の予約を直せる（変更）

- **変更前との差**: 車の画面がカレンダーになり終わった予約も帯で出るのに合わせて、正常フローと、使用中の予約を早く返したときの扱い、AC-1・2・7・8・21 の確かめ方を「予定に出る」から「時間割に帯で出る」へ変える
- **概要**: 予約した本人が、まだ始まっていない予約の車・開始日時・終了日時・行き先・メモを直せる。使用中の予約は、終了日時・行き先・メモだけを直せる（延ばすとき、早く返したとき）。終わった予約は直せない
- **事前条件**: CAR-F-004 で本人が入れた、これからの予約がある
- **正常フロー（変更）**: 予約を開く → 「直す」を押す → 中身を直す → 「保存する」を押す → 車の画面の時間割に、直した中身の帯が出る
- **例外・バリデーション（変更）**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかを空にしたら止め、その項目に「入力してください」と出す
  - 対象外・想定外: 入力の条件は CAR-F-004 と同じ（終了は開始より後、文字数、時間の重なり。長さと何日先までかに上限は無い）。ただし次が違う。

    - API へは、車と開始日時を両方送るか、両方送らないかのどちらか。片方だけを送る要求は形が違うので 400（まだ始まっていない予約でも使用中の予約でも同じ）

    - まだ始まっていない予約を直している間に、その予約が始まったときは、何を変えたかにかかわらず止めて「この予約はもう始まっています。もう一度開いてください。」と出し、最新の予約を出す
    - 開いた後に、本人がほかの端末で直していた、または取り消していたときは、「開いた後に変わっていたとき」の知らせを出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。予約は直す前のまま

- 画面の移り方：URL の `?date=` があれば日の時間割の画面、無ければ月のカレンダーの画面（`?month=YYYY-MM` の月。無い・形が違うときは今月）。`?date=` の形が違うときは今月の月のカレンダーを出す。車が1台も無いときは、どちらの画面でも「車が登録されていません」と車の管理への入口を出す。月のカレンダーで日をタップすると時間割の画面へ移る（履歴を積む。端末の「戻る」で月へ戻れる）。時間割の画面の「月へ戻る」は、その日を含む月のカレンダーへ移る（URL を置き換える。履歴を積まない）。前の月・次の月、前の日・次の日へ移るときは URL を置き換える（履歴を積まない）
- 月のカレンダー：見出しに年月、前の月・次の月・「今日」（今月へ戻る）のボタン。日曜から始まる6週（42日）を出し、ほかの月の日は薄く出す。今日の日は分かる形で出す。日ごとに、その日に一部でもかかる予約を、開始の早い順に、車の色の短い帯（車の名前）で出す（終了がちょうど 0:00 の日には出さない。「使わない」の車は薄く）。3件までは帯で、4件以上は2件を帯で出して残りを「他 n 件」とする。日のセル（帯の上を含む）のどこをタップしても、その日の時間割へ移る。読み込みは、見えている範囲（6週）を `view=range` で1回引く
- 時間割：見出しにその日の日付（「10月10日(土)」）、「月へ戻る」、前の日・次の日のボタン。0:00〜24:00 を縦に並べ、1時間ごとの目盛りと30分の補助の線を出す（1時間の高さは決まった値）。最初の表示位置は、今日なら今の時刻の1時間前、それ以外の日は 8:00。今日なら今の時刻に線を出す。帯は開始から終了までの位置と長さで、車の色（決まった8色の並びの `colorIndex` 番目。9台目からは繰り返す）で塗り、「使わない」の車の帯は薄くする。帯には車の名前（「使わない」を添える）・表示名・時間（`timeRange` の形）・行き先を出す。「使用中」の印は端末の時計で決める（見た目だけ。判定は API）。時間が重なる帯は、重なる帯どうしで幅を分けて横に並べる。帯の右に、帯の無い余白をいつも残す（指で押せる幅。帯のある時間も、そこをタップして枠を出せる）。帯を押すと `/car/reservations/:id` へ。時間割を左右にスワイプすると次の日・前の日へ移る（枠の上で始めたときは枠を動かす操作として扱う）。読み込みは、その日だけを `view=range`（`from` = `to` = その日）で引く
- 枠と、枠から出す入力（CAR-F-004）：時間割の空いた所をタップ（マウスはクリック）すると、タップした時刻を15分刻みに切り捨てた所から1時間の枠を出す。枠の上下の端のつまみを引くと開始・終了が、枠の中を引くと枠ごと（長さはそのまま）が動く。端は引いた所に、枠ごとは引いた量に近い15分刻みにそろえる。枠はその日の 0:00〜24:00 の中で動き、長さは15分より短くならない（23:00 より後をタップしたときは 24:00 で止める。23:30 なら 23:30〜24:00）。枠には開始〜終了の時刻を出す。前の日・次の日・「月へ戻る」で日を移ったとき、帯や「予約する」を押して時間割の画面を離れたときは、枠は消える。枠をタップする（引かずに離す）と入力を出す。枠が出ているときに枠の外の空いた所をタップすると、枠が消える（入力は出さない）。「使う」の車が無いときは枠を出さずに「先に車を登録してください」と車の管理への入口を出す。マウスとタッチは同じ操作（pointer のイベントで扱う）。枠の上では、時間割のスクロールとスワイプを止める。入力は、幅 768px 以上は画面の中央のポップアップ（Mantine の `Modal`）、768px 未満は画面の下から出るシート（Mantine の `Drawer`）。中身は今の `ReservationForm`（開始・終了に枠の時刻を入れる。枠の終了が 24:00 のときは、入力の終了は翌日の 0:00 にする）に「キャンセル」を足したもの。外側を押しても閉じない設定にする（`closeOnClickOutside={false}`）。✕・Esc は「キャンセル」と同じ扱い。入力を開くときに履歴を1つ積み、端末の「戻る」操作も「キャンセル」と同じ扱いにする（時間割の画面から離れない）。入力を閉じたら枠を消す。保存できたら閉じて、予約の開始の日の時間割へ移り（入力で開始の日付を直したときはその日へ移る）、読み直す。二重登録を防ぐ `requestId` は、入力を開くたびに作る
- `ReservationForm`：「キャンセル」を出せるようにする（入力の画面では出さない）
- `ReservationRow`：履歴だけで使う（いつも日付を添える）
- 大きさ：車の画面は遅延読み込み（`React.lazy`）のままにする。FullCalendar を入れる前（T-1）、入れた後（T-6）、外した後のビルドの大きさ（gzip）を tasks.md に残す
- テスト：月のカレンダーと時間割は自作なので、jsdom で DOM を直接確かめる（日のセル・帯・「他 n 件」・枠を、文字とデータの属性（予約の ID・色の番号・「使わない」の印・枠の開始と終了など）で確かめる）。枠の操作は pointer のイベント（`pointerdown`・`pointermove`・`pointerup`）を送って確かめる。jsdom では寸法がすべて0なので、位置から時刻への換算は「時間割の上の端からの距離 ÷ 1時間の高さ（決まった値）」で行い、時間割の上の端の位置を求める所はテストで差し替えられる形にする。スワイプも pointer のイベントで確かめる。指での操作の手ざわり（つまみの押しやすさ・スクロールとのぶつかり）、帯の縦の位置と横の並びの見た目、最初の表示位置、幅 360px・1280px での見た目（COMMON-N-008）は開発環境で手で確かめる
