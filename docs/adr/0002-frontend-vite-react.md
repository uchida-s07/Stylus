# ADR-0002: フロントエンドは Vite ＋ React の SPA にする

- 状態: 採用
- 日付: 2026-09-27
- 関連する spec: specs/001-foundation
- 置き換えた ADR: —
- 置き換えられた ADR: —

## 背景

claude.ai での設計の段階では、フロントエンドを Next.js の静的出力で作る案だった。フロントとバックエンドを分け（ADR-0001）、フロントは Cloudflare Pages の静的ホスティングに置いてスマホのホーム画面から開ける PWA にする。フレームワーク自体へのこだわりは無い。

## 決定

フロントエンドは Vite ＋ React（TypeScript）の SPA にし、PWA にする（vite-plugin-pwa）。ルーティングの React Router、UI ライブラリの Mantine は specs/001-foundation の design.md で決めた。

## 検討した代替案

| 案 | 採らなかった理由 |
|----|----------------|
| Next.js の静的出力 | 静的に出力すると、サーバーで動く機能（サーバー側の描画・API ルートなど）がほぼ使えず、Next.js の制約だけが残る |
| Expo（React Native の Web 版） | ネイティブアプリへ移るときには有利だが、Web 版の完成度と学ぶ量で不利 |

## 結果（トレードオフ）

- 良くなること: ビルドの出力がそのまま静的ファイルになり、Pages に素直に置ける。PWA の仕組みを Vite のプラグインで足せる
- 悪くなること・受け入れたリスク: ネイティブアプリへ移るときは画面を作り直すことになる（引き継げるのは API と `packages/` だけ）。サーバー側の描画が無いので初回の表示は JS の読み込みを待つ（家族4人の利用で、検索エンジン向けの表示も要らないため受け入れる）
