# ADR-0010: 車のカレンダー（月のカレンダーと時間割）を、カレンダーの部品を使わずに自作する

- 状態: 採用
- 日付: 2026-10-17
- 関連する spec: specs/004-car-calendar
- 置き換えた ADR: —
- 置き換えられた ADR: —

## 背景

車の画面を、日付ごとの一覧から、月のカレンダーと日の時間割（0〜24時に予約を帯で出す）に変える（spec 004。CAR-F-004・CAR-F-005）。予約は、時間割の空いた所をタップすると出る1時間の枠を、端で伸び縮み・中で移動（15分刻み）させて時間を選び、枠をタップして入れる。

制約と前提：

- 完全無料の範囲で作る。幅 360px のスマホを基準にし、幅 1280px の PC でも崩れない（COMMON-N-008）
- 日付と時刻はすべて日本時間で出す。父は海外の端末で開くことがあるので、端末の時間帯に頼れない（COMMON-N-009）
- 画面のテストは jsdom で書く（寸法がすべて0）

最初は FullCalendar 7.1.1 の MIT の部分（`@fullcalendar/react` の月・時間割・操作。`temporal-polyfill` が要る）を入れて作った（spec 004 の T-1〜T-12）。`timeZone: 'Asia/Tokyo'` でそのまま日本時間を扱え、jsdom でも帯の文字とデータの属性を読めた（T-1 の V-1）。帯の右の余白も、設定 `dayLaneInnerClass` と CSS の上書きで 48px にできた（T-1 の V-2）。

しかし、開発環境でオーナーが触って確かめたところ（2026-10-16、T-13）、次のことが分かった。

- 長押ししてから引いて範囲を選ぶ操作が使いにくい。Google カレンダーのアプリのような、タップで出た枠を動かす操作は FullCalendar に標準で無い
- 月のカレンダーの日のセルの上の部分を FullCalendar が `aria-hidden="true"` にするため、日のボタンが読み上げから外れる（T-6。テストも役割と名前では探せず、データの属性で探していた）
- 同じ日の2台の予約の印が1つしか出ないなど、月のカレンダーの日の中身を思いどおりに出すには、部品の設定を回り込む作りが増える
- 車ごとに時間割の列を分ける部品（resource-timegrid）は Premium（有料）で、完全無料の制約では使えない

## 決定

- 月のカレンダー（`MonthCalendar`）も時間割（`TimeGrid`）も、Mantine と React で自作する。カレンダーの依存（FullCalendar など）は足さない。`apps/web` の依存から `@fullcalendar/react` と `temporal-polyfill` を外した（T-19）
- 時間割は1列にし、帯を車ごとの色（`GET /cars` の `colorIndex` 番目。決まった8色の並び）で塗って見分ける。時間が重なる帯は、重なる帯どうしで幅を分けて横に並べる（`layoutBands()`）。車ごとの列は作らない
- 日本時間は `@stylus/shared` の日付の部品（`toJstDate()`・`jstStartOfDay()`・`addDays()`・`formatJstTime()` など。Intl を使わず UTC+9 を足して求める）で扱う。端末の時間帯にかかわらず同じ日付・時刻で出す
- 枠の操作は pointer のイベント（`pointerdown`・`pointermove`・`pointerup`）で、マウスとタッチを同じに扱う。位置と時刻の換算は「時間割の上の端からの距離 ÷ 1時間の高さ（48px の決まった値）」で行い（`timeFrame.ts`）、jsdom のテストでも pointer のイベントを送って確かめられるようにする
- 車の画面は遅延読み込み（`React.lazy`）のままにする

## 検討した代替案

| 案 | 採らなかった理由 |
|----|----------------|
| FullCalendar の MIT の部分を使い続ける | 実際に入れて試した（T-1〜T-13）。タップで出た枠を動かす操作が標準で無く、作り込むと部品の設定を回り込む作りになる。日のセルが読み上げから外れる。車の画面の塊が JS 72.98 kB・CSS 3.91 kB（gzip）と重い |
| FullCalendar の Premium の部品（車ごとの列）を使う | 有料で、完全無料の制約に合わない。車は多くても2台で、帯の色で見分けられる |
| ほかのカレンダーの部品を探して入れる | 欲しい操作（タップで出た枠を端・中で動かす）と、日本時間を端末の時間帯から切り離して扱うことの両方を満たすものを確かめる手間が、自作の手間に見合わない。月のカレンダーと1日の時間割だけなら自作でも小さい |

## 結果（トレードオフ）

- 良くなること: タップで出た枠を動かす操作を、Google カレンダーのアプリに近い形で作れる。日のセルをボタンにでき、読み上げとテストで役割と名前で探せる。依存が減り、車の画面の塊が小さくなった（gzip。FullCalendar を入れる前（T-1）→ 入れた後（T-6）→ 外した後（T-19）。車の画面の塊：無し → JS 72.98 kB・CSS 3.91 kB → JS 6.31 kB・CSS 0.97 kB。全体：300.14 kB → 377.63 kB → 308.23 kB。最初に読む JS と CSS の合計は 299.78 kB → 300.38 kB → 300.59 kB でほぼ変わらない）
- 悪くなること・受け入れたリスク: 月のカレンダー・時間割・枠の操作・帯の並べ方を自分で保守する。週の表示や、帯をドラッグして予約を直す操作を後から足すときも自作になる。指での操作の手ざわり（つまみの押しやすさ・スクロールとのぶつかり）と帯の見た目は jsdom で確かめられず、開発環境で手で確かめる
