## 機能要件

### AUTH-F-001 管理者が家族を事前に登録できる

- **概要**: 管理者が、家族一人ひとりのメールアドレス（Google アカウント）・表示名・立場（親・料理担当）・ロール（管理者）を登録する。登録された人だけが家族として扱われる。登録する画面は作らず、管理者が決められた手順（docs/architecture.md の「家族の登録の仕方」）で登録する
- **事前条件**: 管理者が本番・開発の Supabase を操作できる
- **正常フロー**: 管理者が家族のメールアドレスで利用者を作る → その利用者に結びつけて、表示名・立場・ロールを登録する → その家族が Google でログインすると、本人として扱われる
- **例外・バリデーション**:
  - 入力が空・欠けている: メールアドレスか表示名が空（表示名は空白だけも含む）なら、登録を止める
  - 対象外・想定外: 同じメールアドレスを2回登録しようとしたら、2件目を止める。大文字を含むメールアドレスは登録を止める（小文字で登録し直す）。利用者は作られたが家族の登録（表示名・立場）が無い人は、ログインしても家族として扱わない（AUTH-F-002 の未登録と同じ扱い）
  - 処理に失敗: 登録の途中で失敗して片方だけが残った場合は、入れない側に倒れる。利用者だけが残ったときは上の「家族の登録が無い」扱い、家族の登録だけが残ったときはサインアップ無効で弾かれ、どちらも AUTH-F-002 の未登録と同じ表示になる。管理者は手順をやり直す
- **受入基準**:
  - AC-1: Given 管理者が yuriko@example.com を表示名「母」・立場「親」「料理担当」・ロールなしで登録済み / When その Google アカウントでログインし、自分の情報を API に問い合わせる / Then 表示名「母」、立場「親」「料理担当」、ロールなしが返る（出典: specs/001）
  - AC-2: 〔例外：対象外の入力〕Given yuriko@example.com が登録済み / When 同じメールアドレスでもう一度家族を登録する / Then 登録は拒否され、そのメールアドレスの家族は1人のまま（出典: specs/001）
  - AC-3: 〔例外：入力が空〕Given 登録済みの家族がいない / When 表示名を空（""）、または空白だけ（"　"）にして家族を登録する / Then どちらも登録は拒否され、家族は0人のまま（出典: specs/001）
  - AC-4: 〔例外：入力が空〕Given 登録済みの家族がいない / When メールアドレスを空にして家族を登録する / Then 登録は拒否され、家族は0人のまま（出典: specs/001）
  - AC-5: 〔例外：対象外の入力〕Given 登録済みの家族がいない / When メールアドレスを Yuriko@example.com（大文字を含む）にして家族を登録する / Then 登録は拒否され、家族は0人のまま（出典: specs/001）
- **対応する要求**: G-1, J-1
- **出典**: specs/001

### AUTH-F-002 登録された家族が Google でログインできる

- **概要**: ログイン画面の「Google でログイン」から Google アカウントで認証し、登録済みの家族ならアプリのホームに入る。登録されていない Google アカウントでは入れない
- **事前条件**: AUTH-F-001 で本人が登録されている。この端末でログインしていない
- **正常フロー**: アプリを開く → ログイン画面が出る → 「Google でログイン」を押す → Google の画面でアカウントを選ぶ → アプリに戻る → アプリのホームに自分の表示名が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: Google の画面でアカウントを選ばずに戻った（キャンセル）ときは、ログイン画面に戻す。メッセージは出さない
  - 対象外・想定外: 登録されていない Google アカウントのときは、ホームに入れず「この Google アカウントは登録されていません。管理者に連絡してください。」と出し、ログインしていない状態に戻す。ログインしていない状態でホームなどの画面を直接開いたときは、ログイン画面を出す。ログイン済みでログイン画面を開いたときは、ホームを出す
  - 処理に失敗: Google・Supabase・通信のどれかで失敗したときは、「ログインできませんでした。時間をおいてもう一度お試しください。」と出し、ログイン画面に留める
- **受入基準**:
  - AC-1: Given 表示名「母」で登録済みの Google アカウント / When 「Google でログイン」からログインを終える / Then アプリのホームに「母」と表示される（出典: specs/001）
  - AC-2: 〔例外：対象外の入力〕Given 登録されていない Google アカウント / When 「Google でログイン」を押し、Google の画面でそのアカウントを選んでアプリに戻る / Then アプリのホームは出ず「この Google アカウントは登録されていません。管理者に連絡してください。」と表示される（出典: specs/001）
  - AC-3: 〔例外：処理に失敗〕Given ログインの途中で認証に失敗する / When 「Google でログイン」からログインする / Then 「ログインできませんでした。時間をおいてもう一度お試しください。」と表示され、ログイン画面のまま（出典: specs/001）
  - AC-4: 〔例外：対象外の入力〕Given この端末でログインしていない / When アプリのホームの URL を直接開く / Then ログイン画面が出る（出典: specs/001）
  - AC-5: 〔例外：対象外の入力〕Given この端末でログイン済み / When ログイン画面の URL を開く / Then アプリのホームが出る（出典: specs/001）
  - AC-6: 〔例外：対象外の入力〕Given 登録されていない Google アカウントで弾かれた直後 / When アプリを開き直す / Then ログイン画面が出る（出典: specs/001）
  - AC-7: 〔例外：入力が空〕Given 「Google でログイン」を押して Google の画面が出ている / When Google の画面でキャンセルしてアプリに戻る / Then ログイン画面のままで、メッセージは出ない（出典: specs/001）
- **対応する要求**: G-1, J-1
- **出典**: specs/001

### AUTH-F-003 ログインしたまま使い続けられる

- **概要**: 一度ログインすると、ログアウトするまで、アプリを開くたびにログイン画面を経ずにアプリのホームに入れる。少なくとも、最後に開いてから7日以内なら再ログインを求めない
- **事前条件**: AUTH-F-002 でこの端末からログイン済み
- **正常フロー**: アプリを開く → 端末に残っているログイン状態を読む → アクセストークンの期限が切れていれば自動で更新する → アプリのホームが出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 端末にログイン状態が残っていない（初めて開いた、ブラウザのデータを消した）ときは、ログイン画面を出す
  - 対象外・想定外: ログイン状態が無効になっている（長く開かずに失効した、取り消された）ときは、ログイン画面を出す。再ログインは「Google でログイン」から本人だけでできる。家族の登録から外された人は、AUTH-F-002 の未登録と同じ表示にする。使っている最中にアクセストークンの期限が切れたときは、自動で更新して操作を続ける（利用者には見せない）
  - 処理に失敗: 通信できずに更新できないときは、ログイン状態を消さず「通信できません。電波の良いところでもう一度開いてください。」と出す。API やサーバーが失敗を返したとき（DB につながらないなど）も、ログイン状態を消さず「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と出す
- **受入基準**:
  - AC-1: Given 最後に開いてから7日たち、アクセストークンの期限が切れている / When アプリを開く / Then ログイン画面を経ずにアプリのホームが出る（出典: specs/001）
  - AC-2: 〔例外：対象外の入力〕Given 端末に残っているログイン状態が無効になっている / When アプリを開く / Then ログイン画面が出る（出典: specs/001）
  - AC-3: 〔例外：処理に失敗〕Given アクセストークンの期限が切れていて、通信できない / When アプリを開く / Then 「通信できません。電波の良いところでもう一度開いてください。」と表示され、端末のログイン状態は残っている（出典: specs/001）
  - AC-4: Given アプリを開いたまま、アクセストークンの期限（1時間）を過ぎた / When アプリのホームを再読み込みする（自分の情報を問い合わせる API が呼ばれる） / Then 再ログインを求められずに、アプリのホームに自分の表示名が出る（出典: specs/001）
  - AC-5: Given AC-3 のあと通信が戻った / When アプリを開き直す / Then ログイン画面を経ずにアプリのホームが出る（出典: specs/001）
  - AC-6: 〔例外：対象外の入力〕Given 端末にログイン状態が残っているが、家族の登録から外されている / When アプリを開く / Then 「この Google アカウントは登録されていません。管理者に連絡してください。」と表示される（出典: specs/001）
  - AC-7: 〔例外：処理に失敗〕Given この端末でログイン済みで、自分の情報を問い合わせる API が 500 を返す / When アプリを開く / Then 「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と表示され、端末のログイン状態は残っている（出典: specs/001）
- **対応する要求**: J-1
- **出典**: specs/001

### AUTH-F-004 ログアウトできる

- **概要**: ログアウトすると、この端末のログイン状態を消し、ログイン画面に戻る。ほかの端末のログイン状態には触れない
- **事前条件**: AUTH-F-002 でこの端末からログイン済み
- **正常フロー**: 「ログアウト」を押す → 「ログアウトしますか？」の確認で「ログアウト」を選ぶ → この端末のログイン状態が消える → ログイン画面が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら、何もせず元の画面に戻る
  - 対象外・想定外: ログイン状態がすでに無効になっているときも、同じようにログイン画面を出す
  - 処理に失敗: 通信できずにサーバー側の取り消しができないときも、この端末のログイン状態は消してログイン画面を出す
- **受入基準**:
  - AC-1: Given この端末でログイン済み / When 「ログアウト」を押し、確認で「ログアウト」を選ぶ / Then ログイン画面が出て、端末に保存されたログイン状態が消えている（出典: specs/001）
  - AC-2: 〔例外：入力が空〕Given この端末でログイン済み / When 「ログアウト」を押し、確認で「キャンセル」を選ぶ / Then 元の画面のままで、ログイン状態も残っている（出典: specs/001）
  - AC-3: 〔例外：処理に失敗〕Given この端末でログイン済みで、通信できない / When 「ログアウト」を押し、確認で「ログアウト」を選ぶ / Then ログイン画面が出て、端末に保存されたログイン状態が消えている（出典: specs/001）
  - AC-4: Given 端末 A と端末 B でログイン済み / When 端末 A でログアウトする / Then 端末 B のログイン状態は取り消されない（ほかの端末のログイン状態を取り消す要求を送らない）（出典: specs/001）
- **対応する要求**: J-1
- **出典**: specs/001
