## この領域で使うことば

- **当事者**：請求する側と請求先。家族の1人か、「家庭」。「家庭」は父母を1つにまとめた相手として扱う
- **関係者**：当事者が家族の1人ならその人、「家庭」なら父と母の2人
- **空白**：半角空白・タブ・改行と全角空白（U+3000）。家族の表示名（AUTH-F-001）と揃える
- **名義**：請求・精算を誰として行うか。「自分」か「家庭」。「家庭」の名義は親だけが使える（glossary の「立場」（親・料理担当）とは別のことば）
- **側**：請求する側・請求先側、精算の払う側・受け取る側。どの操作ができるかは側で決まる（下の2行）
- **請求の状態**：請求中 → 支払済 → 確認済。ほかに 差し戻し、取消。確認済と取消は終わりの状態で、そこからは変わらない
- **精算**：2人の当事者の間の請求中の請求を、両方向とも差し引いてまとめて払う・受け取ること
- **請求する側の操作**（直す・出し直す・取り消す・受け取った・受け取っていない）は請求する側の関係者が、**請求先側の操作**（払った・差し戻す・「払った」の取り消し）は請求先側の関係者が行う。「家庭」が当事者なら父母のどちらが行ってもよく、経過には実際に操作した家族を残す
- **精算の操作**（まとめて払った・まとめて受け取った・精算ごと戻す）は、含まれる各請求の向きではなく、精算の**払う側・受け取る側**で決まる。払う側の関係者は「まとめて払った」と、精算の「払ったを取り消す」を、受け取る側の関係者は「まとめて受け取った」と、精算の「受け取っていない」を行う

## この領域で共通の振る舞い

- **行えない操作のボタンは出さない**：請求・精算の状態と、自分がどの側かに合わない操作のボタンは、画面に出さない。API でも受け付けない（側が違えば 403、状態が違えば 409）
- **開いた後に変わっていたとき**：画面を開いた後に状態が変わっていて操作が通らなかったときは「請求の状態が変わりました。もう一度開いてください。」と出し、最新の請求を出す。状態は同じで中身（金額など）が変わっていたときは「請求の中身が変わりました。もう一度確かめてください。」、精算に含まれる請求が変わっていたときは「精算の中身が変わりました。もう一度確かめてください。」と出す
- **書き込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度お試しください。」、保存に失敗したときは「保存できませんでした。時間をおいてもう一度お試しください。」と出す。入力した内容は残し、請求・精算は操作の前のまま
- **読み込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度開いてください。」、それ以外は「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と出す
- **知らせの確かめ方**：上の知らせの文言は、代表の受入基準（書き込みは MONEY-F-001/AC-13 と MONEY-F-011/AC-7、読み込みは MONEY-F-004/AC-7・AC-8）で確かめる。各要件の「処理に失敗」は、一部だけが変わらないなど、その要件に固有の結果があるものだけを受入基準にする

## 機能要件

### MONEY-F-001 請求を登録できる

- **概要**: 請求先・金額・カテゴリー・件名・メモ（任意）・発生日を入れて請求を登録する。請求する側は自分。親は「家庭」も選べる。登録した請求は請求中になり、関係者の一覧に出る
- **事前条件**: AUTH-F-002 でログイン済み。カテゴリーが1つ以上ある（MONEY-F-013）
- **正常フロー**: お金の画面で「請求する」を押す → 請求先・金額・カテゴリー・件名・発生日（既定は今日）・メモを入れる。親は請求する側を「自分」か「家庭」から選ぶ（既定は自分） → 「請求する」を押す → 請求中として保存され、一覧に出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 請求先・金額・カテゴリー・件名・発生日のどれかが空なら登録を止め、その項目に「入力してください」と出す。件名は空白だけも空とみなす。メモは空でよい。カテゴリーが1つも無いときは「先にカテゴリーを追加してください」と出し、カテゴリーの追加へ進めるようにする
  - 対象外・想定外: 次の場合は登録を止めて理由を出す。
    - 金額が1円以上9,999,999円以下の整数でない（0・マイナス・小数・範囲外）
    - 金額に全角の数字や数字でない文字が入っている（「半角の数字で入力してください」と出す。全角を半角に直して受け付けることはしない）
    - 件名が50文字を超える。メモが500文字を超える
    - 発生日が今日（日本時間）より後、または 2020-01-01 より前（打ち間違いを止めるため）
    - 自分を請求先にした。親が「家庭」宛てにした。「家庭」として請求するときに、請求先を父か母にした（「家庭」の請求先は息子だけ）
    - 選んだカテゴリーが、登録の直前に削除されていた（「カテゴリーが見つかりません。選び直してください」）

    親でない家族が「家庭」として請求しようとしたら、API が 403 を返す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。「請求する」を続けて2回押しても、登録されるのは1件だけ。通信できないと出た後に入力を直して押し直したとき、最初の登録がすでに保存されていたら、登録を止めて「この請求はすでに登録されています。一覧で確かめて、必要なら直してください。」と出す（API は 409）

  - AC-2: Given 母がログインしている / When 請求する側「家庭」・請求先「くうご」・金額 5,000・カテゴリー「日用品」・件名「スマホの修理代」で請求する / Then 請求する側が「家庭」の請求中の請求ができ、母・父・くうごの一覧に出る（出典: specs/002）
  - AC-3: 〔例外：入力が空〕Given せいごが請求の入力をしている / When 件名を空白だけにして「請求する」を押す / Then 請求は作られず、件名に「入力してください」と出る（出典: specs/002）
  - AC-4: 〔例外：対象外の入力〕Given せいごが請求の入力をしている / When 金額を 0、10,000,000、1.5、-100 のそれぞれにして請求する / Then どれも請求は作られない（出典: specs/002）

### MONEY-F-002 請求中・差し戻された請求を直して出し直せる

- **概要**: 請求する側の関係者が、請求中か差し戻しの請求の金額・カテゴリー・件名・メモ・発生日を直す。差し戻しの請求は、直して（直さなくても）出し直すと請求中に戻る。請求する側と請求先は直せない（取り消して登録し直す）
- **事前条件**: MONEY-F-001 で登録した請求が請求中か差し戻し。操作する人が請求する側の関係者
- **正常フロー**: 請求の中身の画面で「直す」を押す → 項目を直す → 「保存する」（差し戻しのときは「出し直す」）を押す → 保存され、経過に「直した」（差し戻しからは「出し直した」）が日時と操作した家族とともに残る。差し戻しは請求中に戻る
- **例外・バリデーション**:
  - 入力が空・欠けている: MONEY-F-001 と同じ（空の項目があれば止める）
  - 対象外・想定外: 値の範囲は MONEY-F-001 と同じ。支払済・確認済・取消の請求は直せない（「直す」を出さない）。請求先側の関係者は直せない（API は 403）。直す画面を開いている間に相手が払った・差し戻したなどで状態が変わっていたら、保存を止めて「請求の状態が変わりました。もう一度開いてください。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す。請求は直す前のまま
- **受入基準**:
  - AC-1: Given せいご→母 の請求中の請求（3,000円） / When せいごが金額を 2,500 に直して保存する / Then 金額は 2,500円、状態は請求中のままで、経過に「直した」とせいごの表示名が残る（出典: specs/002）

- **正常フロー**: 請求の中身の画面で、請求先側は「払ったを取り消す」、請求する側は「受け取っていない」を押す → 確認で選ぶ → 請求中に戻り、経過に「払ったを取り消した」または「受け取っていない」と操作した家族が残る。精算でまとめて払われたものは、精算の中身の画面で、精算の払う側が「払ったを取り消す」、受け取る側が「受け取っていない」を押す → 確認で選ぶ → 含まれていた請求がすべて請求中に戻り、その精算は戻したものとして残る。各請求の経過に同じ記録が残る
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら何もしない
  - 対象外・想定外: 支払済でない請求は戻せない（戻すボタンを出さない）。確認済は戻せない。精算に含まれる請求は1件だけでは戻せない（請求の中身の画面には戻すボタンを出さず、精算の中身へ進めるようにする。API は受け付けない）。受け取り済み（確認済）の精算と、すでに戻した精算は戻せない（戻すボタンを出さない。開いた後に変わっていたら「精算の中身が変わりました。もう一度確かめてください。」と出す）
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出す。支払済のまま。精算ごと戻すときに一部だけが戻ることはない
- **受入基準**:

  - AC-2: Given 同じ支払済の請求 / When せいごが「受け取っていない」を選ぶ / Then 請求中に戻り、経過に「受け取っていない（せいご）」が残る（出典: specs/002）
  - AC-3: Given せいご→母 3,000円 と 母→せいご 1,000円 を含む精算（母がせいごに 2,000円）が払われている / When せいごが「受け取っていない」を選ぶ / Then 2件とも請求中に戻る（出典: specs/002）
  - AC-4: 〔例外：対象外の入力〕Given せいご→母 の確認済の請求 / When せいごが「受け取っていない」の API を呼ぶ / Then 戻せず、確認済のまま（出典: specs/002）
  - AC-5: 〔例外：対象外の入力〕Given AC-3 の精算に含まれる せいご→母 の請求 / When せいごがその1件だけを戻す API を呼ぶ / Then 戻せず、2件とも支払済のまま（出典: specs/002）
  - AC-6: 〔例外：処理に失敗〕Given AC-3 の精算で、2件を請求中に戻す途中で保存に失敗する / When せいごが「受け取っていない」を選ぶ / Then 2件とも支払済のままで、精算は受け取り待ちのまま（出典: specs/002）
  - AC-7: Given AC-3 の精算（母がせいごに 2,000円）が払われている / When 母が精算の「払ったを取り消す」を選ぶ / Then 2件とも請求中に戻り、各請求の経過に「払ったを取り消した（母）」が残る（出典: specs/002）
  - AC-8: 〔例外：対象外の入力〕Given AC-3 の精算を、せいごが「まとめて受け取った」にした（精算は確認済） / When 母が精算の「払ったを取り消す」の API を呼ぶ / Then 戻せず、精算も含まれる2件も確認済のまま（出典: specs/002）
  - AC-9: 〔例外：対象外の入力〕Given AC-3 で、せいごが「受け取っていない」を選んで戻した精算 / When せいごがもう一度、その精算の「受け取っていない」の API を呼ぶ / Then 戻せず、各請求の経過の「受け取っていない」は1回だけ（出典: specs/002）

  - AC-5: 〔例外：対象外の入力〕Given 親でないせいごのトークン / When 名義「家庭」で精算額の API を呼ぶ / Then 403 が返る（出典: specs/002）

### MONEY-F-011 払う側が精算額を一括で「払った」にできる

- **概要**: MONEY-F-010 の精算で払う側の関係者が「まとめて払った」を押すと、そのとき精算に入っていた請求（両方向とも）がまとめて支払済になり、1つの精算として残る（相手・精算額・含まれた請求・払った家族・日時）。差し引きが 0円 のときは、どちらの側からも押せる
- **事前条件**: MONEY-F-010 で、2者の間に請求中の請求が1件以上ある。操作する人が払う側の関係者（0円のときは2者どちらかの関係者）

### MONEY-N-001 請求は関係者だけが見られ、操作できる

- **概要**: 【セキュリティ】請求・精算は、その関係者だけが見られ、操作できる。関係者でない家族は、管理者を含めて、一覧・合計・中身・精算のどれにも出ない。API は、関係者でない請求・精算を存在しないものとして 404 を返す（あることも知らせない）。関係者でも、請求する側の操作を請求先側が、請求先側の操作を請求する側が行おうとしたら 403 を返す。判定は API で行う（COMMON-N-002）。カテゴリーは家族全員が見られる
- **測り方**: API の自動テスト
- **受入基準**:
  - AC-1: Given せいご→母 の請求 / When くうごがその請求の中身の API を呼ぶ / Then 404 が返る（出典: specs/002）
  - AC-2: Given 母→父 の請求 / When 管理者のせいごが、一覧の API とその請求の中身の API を呼ぶ / Then 一覧にその請求は入らず、中身の API は 404 が返る（出典: specs/002）
  - AC-3: Given せいご→家庭 の請求 / When 父が一覧の API を呼ぶ / Then その請求が入っている（出典: specs/002）
  - AC-4: Given せいご→母 の請求中の請求 / When くうごが「払った」「差し戻す」「直す」「取り消す」の各 API を呼ぶ / Then どれも 404 が返り、請求は変わらない（出典: specs/002）
  - AC-5: Given せいごと母の間の精算 / When くうごがその精算の中身の API と「まとめて受け取った」の API を呼ぶ / Then どちらも 404 が返る（出典: specs/002）
- **対応する要求**: G-7, P-9
- **出典**: specs/002
