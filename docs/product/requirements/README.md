# 常設要件

> システムが「今」満たしている振る舞いを、領域ごとにまとめる。予定は specs/ に書く。
> 書き方の正典は rules.md（~/.claude/skills/product-requirements/rules.md）。

## 領域一覧

| コード | 領域名 | ファイル | 範囲 |
|-------|-------|---------|------|
| COMMON | 全体共通の非機能要件 | common.md | すべての領域にかかる非機能要件 |

## ID の規則

- 機能要件 `<領域>-F-nnn`、非機能要件 `<領域>-N-nnn`、全体共通 `COMMON-N-nnn`。受入基準は `<要件ID>/AC-n`。
- 領域コードは英大文字2〜8文字。この表に登録してから使う。
- 新しい要件の番号は、その領域の常設要件と、進行中（draft / approved）の spec がすでに予約した番号の最大値＋1。
- 常設になった番号は詰めない・振り直さない。廃止した要件は各ファイルの「廃止した要件」表へ移し、番号は欠番にする。
- 無くした受入基準は「AC-n: （廃止）」として番号を残す。
- テスト名（または説明文）に `[<要件ID>/AC-n]` を含める。

## 1要件の書式

各領域ファイルの「機能要件」に、要件ごとに次の5項目を書く（詳しくは rules.md 第4〜6章）。

概要 / 事前条件 / 正常フロー / 例外・バリデーション（3方向）/ 受入基準

あわせて「対応する要求」（vision.md の G-n / P-n / J-n）と「出典」を書く。
