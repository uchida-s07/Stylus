## この領域で使うことば

- **予約**：1台の車を、開始日時から終了日時まで使う予定。予約した家族・行き先（任意）・メモ（任意）を持つ
- **日時**：日本時間で、分まで扱う（秒は持たない）。曜日は日本時間の日付で決める
- **時間が重なる**：同じ車の2つの予約で、一方の開始日時が他方の終了日時より前で、かつ他方の開始日時が一方の終了日時より前のとき。終了日時と次の開始日時が同じ（12:00 に終わり、12:00 に始まる）なら重ならない
- **これからの予約**：終了日時が今より後の予約。そのうち、開始日時が今以前のものを**使用中**と呼ぶ
- **終わった予約**：終了日時が今以前の予約。履歴に出る
- **車の状態**：「使う」か「使わない」。「使わない」の車は、新しい予約の選択肢に出ない
- **予約した本人**：予約を入れた家族。予約を直す・取り消すのは本人だけ（管理者・親も例外なし）
- **空白**：半角空白・タブ・改行と全角空白（U+3000）。お金（MONEY）と揃える

## この領域で共通の振る舞い

- **誰でも見られ、誰でも使える**：車と予約は家族全員が見られる。車の登録・予約は、父を含め家族の誰でもできる（ロール・立場は問わない）
- **行えない操作のボタンは出さない**：本人でない予約、使用中・終わった予約に合わない操作のボタンは、画面に出さない。API でも受け付けない（本人でなければ 403、予約の状態（これから・使用中・終わった）に合わなければ 409）
- **開いた後に変わっていたとき**：画面を開いた後に予約の中身が変わっていて操作が通らなかったときは「予約の中身が変わりました。もう一度確かめてください。」と出し、最新の予約を出す。予約が取り消されていたときは「この予約は見つかりません。」、車が削除されていたときは「この車は見つかりません。」と出す
- **書き込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度お試しください。」、保存に失敗したときは「保存できませんでした。時間をおいてもう一度お試しください。」と出す。入力した内容は残し、車・予約は操作の前のまま
- **読み込みに失敗したとき**：通信できないときは「通信できません。電波の良いところでもう一度開いてください。」、それ以外は「うまく読み込めませんでした。時間をおいてもう一度開いてください。」と出す
- **知らせの確かめ方**：上の知らせの文言は、代表の受入基準（書き込みは CAR-F-004/AC-14・AC-15、読み込みは CAR-F-005/AC-6・AC-7）で確かめる。各要件の「処理に失敗」は、その要件に固有の結果があるものだけを受入基準にする

## 機能要件

### CAR-F-001 車を登録できる

- **概要**: 家族の誰でも、名前を付けて車を登録できる。登録した車は「使う」の状態になり、家族全員の予約の選択肢に出る。最初から車「BMW」が1台（「使う」）登録されている
- **事前条件**: AUTH-F-002 でログイン済み
- **正常フロー**: 車の管理の画面で名前を入れる → 「登録する」を押す → 車の一覧と、予約の入力の車の選択肢に出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 名前が空（空白だけを含む）なら止めて「入力してください」と出す
  - 対象外・想定外: 名前（前後の空白を除いたもの）が20文字を超えたら止める。前後の空白を除いて同じ名前の車（「使わない」の車を含む）があるときは、止めて「同じ名前の車があります」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出し、入力を残す
- **受入基準**:
  - AC-1: Given せいごがログインしている / When 車「ノア」を登録する / Then 母が予約の入力を開くと、車の選択肢に「ノア」が出る（出典: specs/003）
  - AC-2: 〔例外：入力が空〕Given 車の管理の画面 / When 名前を空白だけ（"　"）にして登録する / Then 登録されず「入力してください」と出る（出典: specs/003）
  - AC-3: 〔例外：対象外の入力〕Given 車「ノア」がある / When 「　ノア　」（前後が全角空白）を登録する / Then 登録されず「同じ名前の車があります」と出る（出典: specs/003）
  - AC-4: 〔例外：対象外の入力〕Given 「使わない」の車「ノア」がある / When 「ノア」を登録する / Then 登録されず「同じ名前の車があります」と出る（出典: specs/003）
  - AC-5: 〔例外：対象外の入力〕Given 車の管理の画面 / When 21文字の名前と20文字の名前をそれぞれ登録する / Then 21文字は登録されず、20文字は登録される（出典: specs/003）
  - AC-6: Given アプリを使い始めたばかり（車を誰も登録・変更・削除していない） / When 予約の入力を開く / Then 車の選択肢に「BMW」だけが出て、最初から選ばれている（出典: specs/003）
- **対応する要求**: G-5, J-6
- **出典**: specs/003

### CAR-F-002 車を「使わない」にできる（「使う」に戻せる）

- **概要**: 家族の誰でも、車を「使わない」にできる。「使わない」の車は新しい予約の選択肢から外れるが、車の一覧と、その車の予約（これから・履歴）は残る。「使う」に戻すと、また選択肢に出る
- **事前条件**: CAR-F-001 で車が登録されている
- **正常フロー**: 車の管理の画面で「使わないにする」を押す → 「『ノア』を使わないにしますか？」の確認（その車にこれからの予約があれば「この車にはこれからの予約が N 件あります。予約はそのまま残ります。」を添える）で「使わないにする」を選ぶ → 予約の選択肢から外れ、車の一覧では「使わない」と出る。「使う」に戻すときは「使うに戻す」を押す（確認は出さない）
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら何もしない
  - 対象外・想定外: これからの予約がある車も「使わない」にできる（予約は消さず、本人がそのまま直す・取り消すことができる）。開いた後にほかの家族が同じ操作を済ませていたときは、そのまま成功とする（同じ状態になるだけ）。車が削除されていたときは「この車は見つかりません。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出す。車の状態は変わらない
- **受入基準**:
  - AC-1: Given 「使う」の車「ノア」 / When 母が「使わないにする」を押し、確認で「使わないにする」を選ぶ / Then 予約の入力の車の選択肢に「ノア」が出ず、車の管理の画面では「ノア」に「使わない」と出る（出典: specs/003）
  - AC-2: Given 「使わない」の車「ノア」 / When 「使うに戻す」を押す / Then 予約の入力の車の選択肢に「ノア」が出る（出典: specs/003）
  - AC-3: 〔例外：対象外の入力〕Given 「ノア」にくうごのこれからの予約（10月10日 9:00〜12:00）が1件ある / When 「使わないにする」を押す / Then 確認に「この車にはこれからの予約が1件あります。予約はそのまま残ります。」と出て、「使わないにする」を選んだ後も、その予約は10月10日の時間割に帯で残る（出典: specs/004）
  - AC-4: 〔例外：入力が空〕Given 「使う」の車「ノア」 / When 「使わないにする」を押し、確認で「キャンセル」を選ぶ / Then 「ノア」は「使う」のまま（出典: specs/003）
  - AC-5: 〔例外：対象外の入力〕Given 母が「ノア」の「使わないにする」の確認を開いている間に、せいごが「ノア」を削除した / When 母が「使わないにする」を選ぶ / Then 「この車は見つかりません。」と出る（出典: specs/003）
  - AC-6: Given 母が「ノア」の「使わないにする」の確認を開いている間に、せいごが「ノア」を「使わない」にした / When 母が「使わないにする」を選ぶ / Then 知らせは出ず、「ノア」は「使わない」になっている（出典: specs/003）
- **対応する要求**: G-5
- **出典**: specs/003, specs/004

### CAR-F-003 予約の無い車を削除できる

- **概要**: 家族の誰でも、予約が1件も無い車（取り消した予約は数えない。CAR-F-007）を削除できる。予約が1件でもある車（これから・使用中・終わったのどれでも）は削除できず、代わりに「使わない」にする（CAR-F-002）
- **事前条件**: CAR-F-001 で車が登録されている
- **正常フロー**: 車の管理の画面で「削除」を押す → 「『ノア』を削除しますか？」の確認で「削除する」を選ぶ → 車の一覧と予約の選択肢から消える
- **例外・バリデーション**:
  - 入力が空・欠けている: 確認で「キャンセル」を選んだら何もしない
  - 対象外・想定外: 予約がある車には「削除」を出さない。API で削除しようとしたら止める。画面を開いた後にその車に予約が入ったときは、止めて「この車には予約があるため削除できません。使わないにしてください。」と出す。すでに削除されていたら「この車は見つかりません。」と出す
  - 処理に失敗: 「書き込みに失敗したとき」の知らせを出す。車は残る
- **受入基準**:
  - AC-1: Given 予約が1件も入ったことのない車「ノア」 / When せいごが「削除」を押し、確認で「削除する」を選ぶ / Then 「ノア」が車の一覧と予約の選択肢から消える（出典: specs/003）
  - AC-2: 〔例外：対象外の入力〕Given 終わった予約が1件だけある車「ノア」 / When 車の管理の画面を開く / Then 「ノア」に「削除」は出ず、「使わないにする」が出る（出典: specs/003）
  - AC-3: 〔例外：対象外の入力〕Given 終わった予約が1件だけある車「ノア」 / When 削除の API を呼ぶ / Then 409 が返り、「ノア」は残る（出典: specs/003）
  - AC-4: Given 取り消した予約しか無い車「ノア」 / When 削除する / Then 削除される（出典: specs/003）
  - AC-5: 〔例外：対象外の入力〕Given せいごが「ノア」の削除の確認を開いている間に、くうごが「ノア」を予約した / When せいごが「削除する」を選ぶ / Then 削除されず「この車には予約があるため削除できません。使わないにしてください。」と出る（出典: specs/003）
  - AC-6: 〔例外：入力が空〕Given 予約の無い車「ノア」 / When 「削除」を押し、確認で「キャンセル」を選ぶ / Then 「ノア」は残る（出典: specs/003）
  - AC-7: 〔例外：対象外の入力〕Given せいごが「ノア」の削除の確認を開いている間に、母が「ノア」を削除した / When せいごが「削除する」を選ぶ / Then 「この車は見つかりません。」と出る（出典: specs/003）
- **対応する要求**: G-5
- **出典**: specs/003

### CAR-F-004 車の予約を入れられる

- **概要**: 家族の誰でも、車・開始日時・終了日時・行き先（任意）・メモ（任意）を入れて予約する。日の時間割の空いた所をタップすると1時間の枠が出て、枠を動かして使いたい時間を選び、枠をタップすると、枠の開始と終了が入った入力が出る。「予約する」ボタンから入力の画面を開いて入れることもでき、保存の後はその予約の開始の日の時間割の画面に戻る。同じ車で時間が重なる予約がすでにあれば、後から入れようとした予約は止める（先に入れた予約が優先）。入れた予約は家族全員のカレンダーに出る
- **事前条件**: AUTH-F-002 でログイン済み。「使う」の車が1台以上ある（CAR-F-001）
- **正常フロー**: 車の画面の月のカレンダーで日をタップする → その日の時間割の、使いたい時間の空いた所をタップする → タップした所から1時間の枠が出る → 枠の端を引いて伸び縮みさせる・枠を引いて動かす（15分刻み） → 枠をタップする → 開始日時と終了日時が入った入力が出る（車は「使う」の車が1台だけなら最初から選ばれている） → 車・日時を直し、行き先・メモを入れる → 「予約する」を押す → 予約が保存されて入力が閉じ、時間割に帯が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかが空なら止め、その項目に「入力してください」と出す。行き先・メモは空でよい（空白だけなら空とみなす）。「使う」の車が1台も無いときは、「予約する」を押したときも時間割の空いた所をタップしたときも「先に車を登録してください」と出し（枠は出さない）、車の管理の画面へ進めるようにする。枠から出た入力は、何も保存せずに閉じられ、そのときは時間割の枠も消す。枠が出ているときに、枠の外の空いた所をタップすると枠が消える。入力の外側を押しても閉じない（入れた内容が不意に消えないように）。端末の「戻る」操作は、入力を閉じるだけで車の画面に残る
  - 対象外・想定外: 次の場合は止めて理由を出す。
    - 終了日時が開始日時と同じか前（「終了は開始より後にしてください」）
    - 終了日時が今以前（「終了の日時が過ぎています」）。開始日時は今より前でもよい（乗ってから入れたとき）
    - 行き先（前後の空白を除いたもの）が50文字を超える。メモが500文字を超える
    - 同じ車で時間が重なる予約がある（「その時間は〈表示名〉の予約（〈開始〉〜〈終了〉）と重なっています」。自分の予約と重なるときも同じ）。同時に送られた2つの予約が重なるときは、先に保存された方だけが残る
    - 選んだ車が、入力している間に「使わない」になっていた（「この車は今は予約できません。選び直してください」）、または削除されていた（「この車は見つかりません。」）
    - 枠は、ほかの予約の帯と重なる所へ動かしても、過ぎた時間でも置ける（別の車なら予約できるため。止めるかどうかは「予約する」を押したときに上の条件で決める）。帯をタップすると帯を押したことになるので、帯のある時間は帯の脇の空いた所をタップして枠を出す（出した後に枠を帯の上へ動かせる）。枠はその日の 0:00〜24:00 の中で動き、長さは15分より短くならない（23:00 より後をタップしたときは、枠を 24:00 で止めるので1時間より短くなる）。日を移ると（前の日・次の日・月へ戻る）枠は消える。日をまたぐ予約は、入力で終了の日付を直して入れる

### CAR-F-005 予約をカレンダーで見られる

- **概要**: 家族の誰でも、すべての車の予約を、月のカレンダーと、日の時間割で見られる。車の画面を開くと月のカレンダーが出て、予約が一部でもかかる日に、予約ごとに車の色の短い帯（車の名前）を出す（終了がちょうど 0:00 の日には出さない）。日をタップすると、その日の時間割（0〜24時）の画面に移り、予約を帯で出す。帯は開始から終了までの位置と長さで出し、車ごとの色で塗り、車の名前・予約した家族の表示名・時間・行き先を出す。使用中の予約の帯には「使用中」と出す。時間割の画面からは、前の日・次の日へ移れ、月のカレンダーへ戻れる。先の日も過去の日も見られる。時間割の帯を押すと、その予約の中身（メモを含む）が出る（月のカレンダーの帯を押したときは、その日の時間割へ移る）
- **事前条件**: AUTH-F-002 でログイン済み
- **正常フロー**: アプリのホームで「車」を押す → 今月のカレンダーが出る（前の月・次の月へも移れる） → 日をタップする → その日の時間割の画面に移り、予約が帯で出る（前の日・次の日へも移れる。「月へ戻る」で月のカレンダーへ） → 時間割の帯を押すと、その予約の中身（メモを含む）が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 日に予約が無いときは、月のカレンダーのその日にも時間割にも帯を出さない（知らせは出さない）。車が1台も無いときは、月のカレンダーの画面でも時間割の画面でも「車が登録されていません」と出し、車の管理の画面へ進めるようにする
  - 対象外・想定外: 取り消した予約は出ない（消えているため）。「使わない」の車の予約も出し、帯を「使わない」の車と分かる形（薄く）で出し、時間割の帯の車の名前に「使わない」と添える。日をまたぐ予約は、月のカレンダーではまたいだ日それぞれに帯を出し、時間割ではまたいだ日それぞれに、その日にかかる分の帯を出し、帯の時間は全体を出す（「22:00〜10月11日(日) 2:00」）。別の車の予約が同じ時間にあるときは、時間割ではどちらの帯も隠れずに横に並べて出す。月のカレンダーの1日に入りきらないときは、3件までは帯で出し、4件以上は2件を帯で出して残りを「他 n 件」と出す（日をタップすると時間割ですべて見られる）。予約の中身から車の画面へ戻ったとき、予約を直した後・取り消した後に車の画面へ戻ったときは、その予約の開始の日（直した後は直した後の開始の日）の時間割の画面を出す。時間割の画面から「月へ戻る」と、その日を含む月のカレンダーを出す
  - 処理に失敗: 「読み込みに失敗したとき」の知らせを出す。前の月・次の月、前の日・次の日へ移ったときに読み込めなかったときも同じ知らせを出す

### CAR-F-006 自分の予約を直せる

- **概要**: 予約した本人が、まだ始まっていない予約の車・開始日時・終了日時・行き先・メモを直せる。使用中の予約は、終了日時・行き先・メモだけを直せる（延ばすとき、早く返したとき）。終わった予約は直せない
- **事前条件**: CAR-F-004 で本人が入れた、これからの予約がある
- **正常フロー**: 予約を開く → 「直す」を押す → 中身を直す → 「保存する」を押す → 車の画面の時間割に、直した中身の帯が出る
- **例外・バリデーション**:
  - 入力が空・欠けている: 車・開始日時・終了日時のどれかを空にしたら止め、その項目に「入力してください」と出す
  - 対象外・想定外: 入力の条件は CAR-F-004 と同じ（終了は開始より後、文字数、時間の重なり。長さと何日先までかに上限は無い）。ただし次が違う。
    - 直す前の自分の予約とは、重なりを数えない
    - API へは、車と開始日時を両方送るか、両方送らないかのどちらか。片方だけを送る要求は形が違うので 400（まだ始まっていない予約でも使用中の予約でも同じ）
    - まだ始まっていない予約は、終了日時が今以前になる直し方はできない（「終了の日時が過ぎています」）
    - 使用中の予約は、車と開始日時を変えられない（入力欄を出さず、送らない。API に車・開始日時を両方含めて送ったら、値が同じでも 409）。終了日時は開始日時より後なら今より前にしてもよい（早く返した時刻を残す）。そうした予約は終わった予約になり、履歴にも出る（時間割の帯には「使用中」が出なくなる）
    - 「使わない」の車へは移せない（「この車は今は予約できません。選び直してください」）。予約している車が「使わない」になっていても、車を変えずに直すことはできる。移す先の車が、直している間に削除されていたら止めて「この車は見つかりません。」と出す
    - 本人でない予約には「直す」を出さない。API で直そうとしたら 403
    - 終わった予約には「直す」を出さない。API で直そうとしたら 409。直している間に予約が終わったときは「この予約はもう終わっているため直せません。」と出す
    - まだ始まっていない予約を直している間に、その予約が始まったときは、何を変えたかにかかわらず止めて「この予約はもう始まっています。もう一度開いてください。」と出し、最新の予約を出す
    - 開いた後に、本人がほかの端末で直していた、または取り消していたときは、「開いた後に変わっていたとき」の知らせを出す
