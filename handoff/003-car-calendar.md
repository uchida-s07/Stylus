- [ ] D-2: カレンダーの形（スマホの幅 360px でも見やすいことが前提。COMMON-N-008）
  - 案 a（推奨）: 月のカレンダー＋その日の時間割。上に月のカレンダー（予約のある日に印）、選んだ日の下に縦の時間割（0〜24時、予約を帯で）。スマホでも横にはみ出さない
  - 案 b: 週の時間割（縦に時刻・横に7日）。PC では見やすいが、360px では1日の列が細く、帯の文字が読めない（スマホでは3日に減らすなどの手当てが要る）
  - 案 c: 車を行にした横の時間軸（1日または数日）。車ごとの空きが分かりやすいが、今は車が1〜2台で利点が小さい
- [ ] D-3: どこまでの日を見せるか：これからの予約だけ（今の API で足りる）か、過去の日も見せるか（期間で引く API を足す。履歴の画面と重なる）
- [ ] D-4: 予約の登録の操作
  - 案（推奨）: 時間割の空いている所を押すと、その時刻（30分単位）を開始、1時間後を終了にして入力の画面（またはシート）を開き、そこで車・終了・行き先・メモを直して登録する。ドラッグで範囲を選ぶ操作は、スマホではスクロールとぶつかりやすいので入れない
  - 決めること：押した時刻の刻み（30分 / 1時間）、入力を別の画面にするか画面の下から出るシートにするか、直す画面（`/car/reservations/:id/edit`）も同じ操作にするか

- [ ] D-6: 部品の作り方：新しい依存を足さず Mantine で自作する（推奨。月のカレンダーだけ `@mantine/dates` を使う案もあるが、003 の計画では足さなかった）か、カレンダーの依存（FullCalendar など）を足すか。足すなら、大きさとライセンスを確かめる（CLAUDE.md「新しい依存パッケージを追加するときは…」はフロントでも同じに扱う）

## 5. 進め方のメモ（この PC での作業）

- 依存は `corepack pnpm install --frozen-lockfile` で入っている。Bash からは `pnpm` が見つからないので、`node_modules/.bin/vitest` などを直接呼ぶか、PowerShell で `corepack pnpm …` を使う
- テストは並列数を4に絞る：`node_modules/.bin/vitest run --maxWorkers=4`（既定の並列数だと、web と repo-checks の一部が時間切れで落ちる。この PC の負荷のため）。API のテストは `apps/api/vitest.config.ts` で時間の上限を 30 秒に広げてある
- 画面のテストで端末の時計を固定するときは `apps/web/test/car.ts` の `setDeviceClock`（Date だけを差し替える）。車の画面のテストの部品（`installCarApi`・`reservation`・`carItem`・`fillDateTime` など）も同じファイルにある
- 開発環境へ流すときは `gh workflow run deploy-api.yml --ref <ブランチ>`（spec ブランチへの push では流れない）。実行の見守り（`gh run watch`）は自動モードで止められるので、結果はオーナーに Actions の画面で見てもらう
